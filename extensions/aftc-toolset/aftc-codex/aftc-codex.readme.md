# aftc-codex — feature companion doc

An opt-in knowledge base for pi. It injects the maintainer's unified coding rules +
thinking-and-action guidance + a generated resource list into the model's system
prompt, and gives the model a `codex_load` tool to fetch the full topic doc for a
technology only when it is relevant. Off by default. Enable with `/codex-enable`,
prep with `/codex-init`, configure through the `/aftc-codex` menu.

The authoritative build spec (decisions, edge cases, safety principles) is
`.dev/codex-build-documentation.md` (a dev/build doc - npmignored, not
shipped, not part of the user's codex data).

## What it adds to the extension

- A `codex_load` model tool (fetch a topic doc on demand).
- `before_agent_start` system-prompt injection of the stable rules + guidance + list.
- A durable per-session `prepped` state + a fresh-session prep notice.
- A `context`-event prune filter (removes stale docs as matched pairs).
- Project technology auto-detection.
- A self-education loop (`/aftc-codex-learn`).
- The `/aftc-codex` config menu + the `/aftc-codex-*` commands.
- The `aftc-codex` skill (model-facing guidance).

## The two-copy model (and why)

pi replaces the whole package directory on `pi update`, wiping anything inside it.
So the knowledge base lives in TWO places:

- Shipped seed (source only): `extensions/aftc-toolset/data/aftc-codex/`
- User live copy (per-user): `<dataDir>/aftc-codex/`
  (`%APPDATA%\pi-aftc-toolset\data\aftc-codex\` on Windows;
  `~/Library/Application Support/pi-aftc-toolset/data/aftc-codex/` on macOS;
  `$XDG_DATA_HOME/pi-aftc-toolset/data/aftc-codex/` or
  `~/.local/share/pi-aftc-toolset/data/aftc-codex/` on Linux).

The shipped seed mirrors the live-copy layout - seed `data/aftc-codex/<x>` maps
1:1 to `<dataDir>/aftc-codex/<x>`, and only its CONTENT is copied
into `<dataDir>/aftc-codex/`. The live copy survives `pi update`. The seed is
curated SOURCE only - it never contains generated/runtime files
(`codex-resource-list.md`).

The codex root is always the data-dir copy (`<dataDir>/aftc-codex`); there is
no override. The copy is strictly one-way: seed -> live.

## Resource layout

```
<dataDir>/aftc-codex/
├── resources/
│   ├── codex-resource-list.md        # AUTO-GENERATED by the sync script (not shipped)
│   ├── codex-rules.md                # unified rules + self-learning/usage instructions
│   ├── thought-and-action-guidance.md
│   ├── markdown-guidance.md
│   ├── languages/  libraries/  frameworks/  engines/  tools/  runtimes/
│   └── (ANY extra folder is discovered dynamically - known five list first)
```

The folder is only organisation - `codex_load` and detection search across ALL
category folders, so a file's folder does not matter for retrieval.

## The sync script

`scripts/sync-codex-resources.mjs` (Node ESM) regenerates
`codex-resource-list.md` from the live resources. Two callers: the extension spawns
it (child_process, arg array, no shell; falls back to `process.execPath`) as the
first step of every resource command; the model runs it via bash after manual edits
(the injected rules embed the absolute `node <script>` command).

Byte-stable (cache-critical - the list rides the system-prompt prefix): deterministic
sort, no timestamps, atomic write (tmp + rename), and the write is SKIPPED entirely
when the content is unchanged. Never throws (exit 0 with a note on error).

## Injection + prune mechanics

Hybrid, cache-friendly design:

- Stable always-on content (`codex-rules.md` + `thought-and-action-guidance.md` when
  `aftcCodexInjectGuidance` + `codex-resource-list.md`) rides the CACHED system-prompt
  prefix via `before_agent_start` returning `{ systemPrompt }`. Read fresh from disk
  each turn (byte-stable files -> no prefix churn). Never pollutes history, never
  accumulates, resume-proof. Injected only when `enabled && prepped && !silent`.
  **Cache note:** on the FIRST turn after prepping, pi's cache diagnostics may show
  "Warning: Cache prefix changed: system" — this is expected and harmless (the prefix
  went from no-codex to +29KB codex). Every subsequent turn the prefix is byte-identical
  and cache-hits normally. Ignore this one-time warning.
- A lightweight marker custom message (`aftc-codex-marker`) is the detectable/prunable
  "codex presence" in history: a short visible note + the instruction to fetch docs
  via `codex_load`. When autoLoad is on, detected project topics are appended.
- `prepped` / `silent` are per-session and durable: persisted via
  `pi.appendEntry("aftc-codex-state", …)` (a custom entry - NOT in LLM context),
  restored on `session_start`. `silent` resets each session; `prepped` survives
  compaction and resume.
- Fresh-vs-resume uses `session_start.reason` (no `getEntries()` heuristic): fresh =
  `new`/`startup` (stand-out transcript notice in TUI, auto-prep in print); restore =
  `resume`/`reload`/`fork` (no nagging).

Pruning (`context` event) is a NON-DESTRUCTIVE filter of the LLM-bound deep copy
(stored history is untouched - pi cannot delete a stored entry):

- `codex_load` docs are removed as matched tool_use + tool_result PAIRS (the ToolCall
  block is stripped from the assistant message AND its tool_result message removed) so
  a tool_use is never orphaned. An assistant message emptied by pruning is dropped.
- When `!enabled || silent` -> ALL codex (markers + docs) is removed.
- Otherwise the latest generation of docs (the last assistant message with `codex_load`
  calls) and the latest marker are kept; older ones are pruned.
- Non-codex messages/tool pairs are never touched.

## Detection

`codex-detect.ts` scans a cwd and maps signals to topic docs: file extensions
(`.ts`->typescript, `.py`->python, `.gd`->godot, ...), `package.json` deps
(`three`->threejs, `chart.js`->chartjs, gsap, puppeteer, vite, ...), and marker files
(`Dockerfile`->docker, `composer.json`->php+composer, `pyproject.toml`->python,
`project.godot`->godot, a `pi` manifest->pi-extension). The result is intersected with
the resources actually present and cached per cwd. Bounded: skips heavy dirs
(`node_modules`, `.git`, `dist`, `.venv`, `__pycache__`, any dot-dir), caps depth (6)
and files visited (8000). When `aftcCodexAutoLoad` is on, `/codex-init` names the
detected topics in the marker.

## The self-education loop

`/aftc-codex-learn` injects instructions (a user message) telling the model to persist
DURABLE, GENERAL lessons using its standard tools: sync first; consult the resource
list (update, never duplicate); write entries (auto-add with uniqueness checks by
default, or propose-then-confirm) in the canonical format (`[ID] LEAD_TOKEN - symptom`
/ `Cause:` / `Fix: (YYYY-MM)`; `[ID]` is a short token unique within the file), routing
thinking lessons -> `thought-and-action-guidance.md` and tech gotchas -> the right
category doc; sync after. The prompt names the live OS-data copy as the write target
(the package seed is read-only) and tells the model to decide routing/format in one
pass and report empty buckets honestly rather than pad — guardrails added after a
session whose learn loop burned most of its budget on meta-deliberation.

## Updates (one-way copy)

There is no merge / drift / backup machinery. The codex is a strict one-way
copy from the shipped seed to your live data-dir copy; your live edits (e.g.
via `/aftc-codex-learn`) are never auto-overwritten. To take the shipped
defaults again, use Start Fresh (or `/aftc-codex-install`), which deletes the
live copy and re-seeds it (irreversible, confirmed).

## The codex_load tool

`codex_load(topic)` reads a topic doc on demand - searches across ALL category folders
+ top-level, fuzzy aliases (`ts`/`py`/`js`/`pine`/`gd`), specials
(`rules`/`guidance`/`list`/`markdown`), strips a leading `@`, drops a trailing `.md`,
supports explicit `category/name`. Truncates huge files (`truncateTail`, 50 KB / 2000
lines) and states where the full file is. Throws on an unknown topic with the valid
list. Has a `promptSnippet` + `promptGuidelines` naming the tool.

## Commands

`/aftc-codex` (menu), `-enable` (enable + prep; warns if already active; alias
`/codex-enable`), `-disable` (disable + strip all codex from context; alias
`/codex-disable`), `-install` (fresh install or re-install), `-init`, `-refresh`,
`-learn`, `-status`. The resources menu, `-learn` and `-install` run the
list-regeneration script first; pure toggles skip the spawn.

## Config preferences (config.json)

`aftcCodexEnabled` (false), `aftcCodexInjectGuidance` (true), `aftcCodexAutoLoad`
(true), `aftcCodexSeeded` (false), `aftcCodexAutoAddEntries` (true). All migrated
into an existing config.json via the write-back pattern. (The former
`aftcCodexThoughtLog` and `aftcCodexRoot` prefs were removed in v1.13.2.)

## Events subscribed

- `before_agent_start` - inject the rules/guidance/list block.
- `context` - prune accumulated codex docs + markers.
- `session_start` - restore state; fresh-session notice / print auto-prep.

## Production-safety invariants (binding)

1. Never destroy user data - seeding is copy-only (never overwrites); the only
   destructive actions (Start Fresh, re-install) are explicit + confirmed.
2. Never break a session - pruning is a non-destructive `context` filter only; never
   `branch()`/`resetLeaf()`.
3. Fail soft - every I/O op is best-effort try/catch -> safe default / no-op.
4. Off by default.
5. Idempotent + resumable - seed/list-regen re-run safely.
6. Copy-only seeding - never overwrites an existing file.
7. One-way copy - the seed never auto-overwrites a live file; user edits persist.
8. Destructive actions (Start Fresh, re-install) are confirmed and irreversible by design.
9. No surprise context pollution - codex is injected only when enabled + prepped.
10. Bounded resource use - no processes/timers in the factory.
11. Cross-platform correctness - Node `os`/`path`; no shell assumptions.
12. Privacy - no prompt/response text recorded; no credentials.
13. Packaging safety - never ship user data or generated/runtime files; seed is source only.
14. Value-preserving migrations - config write-back preserves existing values.
15. Reversibility - enable, seed, prune each have an undo path (disable / re-seed).

## Failure modes

- Not seeded -> injection finds no rules -> nothing injects; `-on`/`-run` seed first.
- Missing/corrupt resource -> safe fallback (empty/defaults).
- `node` missing -> sync spawn falls back to `process.execPath`, then no-ops.
- Menus no-op outside TUI; print mode reports without menus.

## Cross-platform

Paths via Node `path`/`os`; copy via `fs.copyFileSync`; checksums via `node:crypto`;
sync spawn via `node:child_process` argument arrays (no shell). Windows/Linux/mac
(mac best-effort - no test host).
