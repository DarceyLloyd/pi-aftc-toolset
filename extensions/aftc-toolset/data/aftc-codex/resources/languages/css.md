## Gotchyas

- [fA8kP2] animation fill-mode `both` traps position:fixed descendants - the fill keeps the final keyframe's `transform` (even `translateY(0)`) applied forever, and a transformed ancestor becomes the containing block + stacking context for fixed descendants, so dropdowns/popups render UNDER later siblings; use fill-mode `backwards` for enter animations whose end state is the natural state (no lingering transform).
- [sQ7mF3] flex-column scroll container squashes items instead of scrolling - children default to `flex-shrink: 1`, so an overflowing `flex` column list COMPRESSES its items (cards collapse to thin strips, `scrollHeight == clientHeight`, scrollbar never appears); set `flex: none` (flex-shrink: 0) on the items so they keep their height and the container actually scrolls.
- [gU8sB4] Fixed table header above a scrolling body misaligns columns - the body's scrollbar steals ~13-15px of content width the header does not have, so grid columns computed in `fr` drift apart (visible once you compare header vs row boundaries); use `scrollbar-gutter: stable` on the body so the gutter is always present, and either give the header the same gutter inset or use a fixed-px first column (resizable via CSS var) so only the fluid column absorbs the difference.

- [9s6pyq] Global * { box-sizing: border-box } & JS size measurement - libs that read a container's getComputedStyle width/height to size content assume content-box and over-size by the padding (content runs under scrollbars/edges); give the measured container box-sizing: content-box (or zero padding). Concrete instance: xtermjs.md fit addon.

- [z9Abuo] A global `@media (prefers-reduced-motion: reduce){ *,*::before,*::after{ transition-duration:.001ms!important; animation-duration:.001ms!important } }` nuke silently kills EVERY transition + animation (drawers, modals, hovers, carousels) on the many dev machines that have the OS reduce-motion flag ON - so the whole site reads as "transitions disappeared" even though every partial still declares them; if the project ships its motion, do NOT add this rule (and when debugging "no transitions", check getComputedStyle transition-duration + whether the flag is reduce before blaming the CSS).

## Issues & Solutions


- [CvqlBV] SVG icon renders hollow/outlined instead of filled, even though its `<path>`/`<symbol>` defines solid shapes
  Cause: a global icon utility class such as `.ic{fill:none;stroke:currentColor;stroke-width:2}` forces every icon to stroke-render (outline).
  Fix: scope a filled override only where solid glyphs are needed, e.g. `.p-btn .ic{fill:currentColor;stroke:none}` (higher-specificity descendant selector wins over the bare `.ic`). (2026-07)
- [Dxlcme] `url()` stored in a CSS custom property 404s - or, behind a `mask`, makes the element VANISH with no console error - even though the file exists at the document-relative path
  Cause: a `url()` inside a var resolves relative to the stylesheet where the `var()` is CONSUMED, not where the custom property is declared and not relative to the HTML document. So an inline `style="--art:url(images/x.svg)"` consumed by `mask:var(--art)` in a stylesheet two levels deep (eg `css/pages/home.css`) looks for `css/pages/images/x.svg`, not the document-root `images/x.svg`. A failed `mask-image` is treated as fully transparent, so the masked element silently disappears with zero console errors.
  Fix: use the correct relative path FROM the consuming stylesheet's location to the asset - eg `--art:url(../../images/x.svg)` if the stylesheet is two directories deep. Count the `../` to match the stylesheet's actual depth relative to the target asset. Do NOT use root-absolute (`/images/x.svg`) unless the project is guaranteed to be served from the domain root - if the project lives in a server subdirectory, root-absolute still 404s. (2026-07)
- [gDwLEs] Clicks silently do nothing on the whole page / `document.elementFromPoint(x,y)` over a button returns some unrelated `position:fixed` overlay (e.g. `DIV.modal`) even though that overlay is "closed"
  Cause: the author rule sets `display` on the element (`.modal{display:flex}`, also `.cart`, fullscreen-nav `.fs`, off-canvas `.drawer/.oc`), and an author `display` beats the user-agent `[hidden]{display:none}` (the UA rule is not `!important`), so a `hidden` overlay stays laid out at `inset:0` as an invisible, full-viewport click-trap (programmatic `el.click()` still works because it bypasses hit-testing, which is why it fools you).
  Fix: add a global `[hidden]{display:none !important}` AND set `pointer-events:none` on overlay containers until they carry their open class (`.modal:not(.open),.cart:not(.open),.fs:not(.open),.drawer:not(.open),.oc:not(.open){pointer-events:none}`) so even the fade-out window can't trap clicks. (2026-07)
- [qEIyEI] A grid item with `aspect-ratio` + `height:auto` + `justify-self`/`align-self:center` collapses to ZERO size (invisible box)
  Cause: with no definite height and centred alignment the item's cross size resolves to its in-flow content, which for an art panel is an absolutely-positioned `::before`/mask = 0, so the whole box vanishes (reads as an empty hero half).
  Fix: Give it a definite height alongside aspect-ratio, e.g. `height:min(380px,64vh)`, never `height:auto`. (Sibling silent trap already logged: `overflow-x:hidden` on body creates a scroll container and kills `html{scroll-behavior:smooth}` - use `overflow-x:clip`.) (2026-07)
- [Y6kH3m] SVG sprite icons rendered via `<svg class="i"><use href="#i-..."/></svg>` show up as huge black blobs that overflow their button / nav containers
  Cause: no CSS sizing rule targets the `<svg>` element itself; the browser falls back to the default inline SVG size (~300x150 px or 100% of the containing block) and renders all `<path>`/`<circle>` children with the default fill (black) because no `fill`/`stroke` was set in CSS - the symbol definitions carry no presentation attributes.
  Fix: define a single global utility class for sprite icons (e.g. `svg.i{ display:inline-block; width:1.1em; height:1.1em; flex:none; fill:none; stroke:currentColor; stroke-width:2; stroke-linecap:round; stroke-linejoin:round; }` for outlined icons, or the same but with `fill:currentColor;stroke:none` for solid glyphs). Then either let `width:1em` inherit the parent font-size, or add a fixed-size override per container (e.g. `.icon-btn svg.i{width:18px;height:18px}`). Never leave the SVG without both sizing and fill/stroke - the missing-rule default is the worst possible look. (2026-07)
- [hN4kB7] A cart-drawer / off-canvas panel opens but is invisible - the close (X) button does not appear either, the page is just blank on the right edge
  Cause: the drawer's open state is wired to a CSS transform (`transform: translateX(0)` vs `transform: translateX(102%)`), but the drawer's `width` is left at `100%` of the viewport. When off-screen, the 100%-wide panel is translated 102% to the right so it sits outside the viewport, but the panel's box still takes layout space at 100% - pushing the page to render at double the viewport width and causing a horizontal scrollbar (or just being clipped without any visual feedback).
  Fix: (a) make the off-screen transform `translateX(100%)` (NOT 102%) so the panel sits flush at the right edge of the viewport when closed, (b) give the drawer an explicit width `width: min(420px, 96vw)` AND set the off-screen translate to `100%` so it never exceeds its own width, (c) add `overflow-x: hidden` (or `clip`) on the body to belt-and-brace prevent a horizontal scrollbar. Combine with `transition: transform 0.3s` for the slide. (2026-07)
- [kF2hD8] A newly added full-page view renders UNDERNEATH the site's `position:fixed` header (top of the page hidden behind it)
  Cause: the existing top-level views each carry a header-height offset (eg `padding-top:calc(var(--hdr-h) + 30px)`), but the new view was given only a small cosmetic `padding-top`. When it swaps in (siblings set to `display:none`) its content starts at viewport y=0, sliding under the fixed header - no console error, reads as "misaligned".
  Fix: copy the header-height compensation pattern from the sibling views (typically `padding-top:calc(var(--hdr-h) + N)`), not an arbitrary value. When verifying, measure the first CONTENT element's top against the header's bottom - the section box itself is at y=0 by design because padding lives inside its border-box. (2026-07)
- [T2bX8P] A "Buy box" / sidebar element sticks to the top of the viewport on scroll, but its `position: sticky` "stops working" once the page scrolls past the section above it
  Cause: the page is wrapped in a `display: flex` column with the sidebar as a sibling. The flex container makes each child a `flex item`, and `position: sticky` on a flex item only sticks within ITS flex item's bounds - which is the entire column height, so the sticky behaviour never triggers. (Same trap with grid items.)
  Fix: keep the sticky element OUTSIDE the flex/grid layout - render it as a regular block sibling, or wrap just the sticky item in a non-flex/grid container, or use `align-self: start` on the sticky child so it does not stretch to fill the flex column (a stretched element has no "scroll within me" boundary). Alternatively use `position: sticky` with a `top: 0` and verify the closest scroll container is the viewport (not a flex item with its own overflow). (2026-07)

- [bN7qR4] Button-styled anchors (.btn) render with link colours / unreadable text inside a content area, even though .btn sets color explicitly
  Cause: a blanket id-scoped element rule like `#content a{color:...}` has specificity (1,0,1) and beats the component class `.btn` (0,1,0) regardless of source order - every anchor-button in the content area gets link ink.
  Fix: scope blanket text-link rules to their real targets with :not() - `#content a:not([class*="btn"]){...}` - so component classes always win for their own elements; same trap as `#content button` catch-alls (class every button instead). (2026-07)
- [kP4wQm] Text inside a padded container renders ~80px below the top (phantom blank lines) even though padding/margins are correct
  Cause: white-space: pre-wrap on the CONTAINER also preserves the HTML source whitespace BETWEEN its child divs (the newlines + indentation in the markup), generating anonymous block boxes that render as blank lines above the content. No computed-style metric exposes it (padding/margin/display all look right; offsetTop is just ~90px).
  Fix: put white-space: pre-wrap on the TEXT element only, never on the container; the container keeps normal white-space so source formatting whitespace collapses. Verify with a headless screenshot + getBoundingClientRect of the text vs the container top. (2026-07)
