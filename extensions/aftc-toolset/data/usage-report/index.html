Context figures come from pi's own context estimate at task start (message sent) and task end (after the final answer), divided by the model's declared context window. Tasks until full = how many tasks of the current average growth would fill the window. 1M-window flag fires when a model already burns more than 1,000,000 tokens per 5 hours — at that rate a 1M context window cannot be sustained. The 5h / weekly allowance is provider-reported (a snapshot before and after each task); providers without an allowance endpoint show N/A. Token burn rates are computed for every model.

A failed call is an assistant turn that ended with an error: rate limited (429), overloaded (5xx), model/endpoint not found (404), auth failures, timeouts, network problems, a full context window, or a transport abort. Your own aborts (Escape) are not errors — they are counted as a stat on the Timings tab. The error rate divides a provider's failed calls by its completed tasks — outages, rate limits and network faults hit every model on a provider, so reliability is judged per provider, never per model.

Tool errors are tool calls that failed (wrong arguments, stale edit anchors, bad regex, missing files or binaries, timeouts) — a model-misuse signal, distinct from the provider failures above. A "Repeated" count shows how many times the same normalised mistake recurred. Provider errors (timeouts, 4xx/5xx, HTTP status codes) stay the primary section above.
