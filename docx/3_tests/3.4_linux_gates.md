## Function

Two Docker-Compose gates that verify the package on Linux (the extension
ships cross-platform). Dev tooling — tagged `dev-tool`, 1500 s watchdogs.

## Suites

| Suite | Compose services | Purpose |
| --- | --- | --- |
| `pi-linux-integration` | `pi-linux` | Live-prompt Linux integration: runs pi inside the container with the package installed and exercises real prompts. CONSUMES PROVIDER ALLOWANCE — copies the local `auth.json` in transiently (removed afterwards). |
| `pi-linux-ssh-verify` | `pi-client`, `ssh-target` | Full Linux gate WITHOUT provider allowance: `/aftc-install`, the unit suites, the carrier's own pytest, and client→target SSH end-to-end. |

## Verification cycle (AGENTS.md, normative)

1. Copy the latest package files to `/opt/pi-aftc-toolset` in the container.
2. Run `pi -p /aftc-install` as user `pi` AFTER the copy.
3. Check exit status — an install failure is fixed on WINDOWS first.
4. Only then run the Linux tests.
5. A Linux failure → fix on Windows → verify Windows → restart at step 1.

Container definition: `tests/pi-linux-integration/` (Dockerfile +
docker-compose.yml); runs pi as user `pi`. Never push container
state/credentials to any registry.

## Host access & disable

- Host access: Docker Desktop; compose services are reachable only within
  the compose network (client→target); no published host ports needed.
- Disable: skip the gates — they are release-time checks (the "Linux last"
  workflow order), not part of ordinary iteration.
