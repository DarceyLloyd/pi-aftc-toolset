## Function

End-to-end SSH suites that spin a disposable Docker SSH fixture and drive
the real carrier/extension against it. Dev tooling — tagged `dev-tool`:
not part of the shipped product, documented with host access + disable
instructions per the dev-tool rule.

## Suites

| Suite | Timeout | Covers |
| --- | --- | --- |
| `ssh-local-path-check` | Docker | Upload/download local path handling (quotes, relative paths, `@` stripping) (1.6.1) |
| `ssh-idle-self-exit-check` | Docker | Sidecar idle self-exit (`AFTC_SSH_IDLE_TIMEOUT_SEC`) + reconnect (1.6.10.2) |
| `ssh-idle-connection-lost-check` | Docker | Monitor prunes a dropped session; idle exit afterwards |
| `ssh-nano-keys-check` | Docker | Drives nano through the PTY shell tools (1.6.9/1.6.10.2) |
| `ssh-replacement` | 600 s | The full regression: commands, SFTP, port forwarding, PTY against a disposable SSH fixture (1.6 + 1.6.10) |

Also related: `tests/install-test/Dockerfile` — container used to verify
`/aftc-install` from a clean image.

## Host access & cleanup

- Docker Desktop (Windows) runs the fixtures locally; suites manage their
  own container lifecycle.
- Cleanup: `clear-docker.bat` at the repo root removes all containers +
  the test images/networks (2.4). Never push container state or
  credentials to any registry (AGENTS.md).

## Disable

Skip these suites to run without Docker — nothing else depends on them;
local suites (3.2) cover the protocol/lifecycle logic with a fake carrier.
