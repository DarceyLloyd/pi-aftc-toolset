`tests/readme.md`, normative).

## Harness mechanics

- One folder per check: `tests/<name>/<name>.mjs` + own README + fixtures.
- Plain Node ESM; extension TS loaded via jiti from the GLOBAL pi install
  (`PI_CODING_AGENT_PATH` overrides the location) — tests run the same
  loader pi uses.
- Mock `ExtensionAPI`/`ctx` objects; overlays driven headlessly through
  their `handleInput`; injectable deps where modules expose them
  (`KeysDeps.copy`, `QuickOpenDirDeps`, `SshCarrierOptions.spawn`, …).
- Paths from the script location, never `process.cwd()`.
- Use dependencies already in the project tree; no network for ordinary
  tests; never automate visual UI checks.

## Watchdog timeouts (non-negotiable)

Near the top of EVERY script:
`setTimeout(() => process.exit(2), N).unref()`.

| Class | Timeout |
| --- | --- |
| Pure-mock / no I/O | 20 s |
| Module-load + jiti | 30 s |
| SSH / carrier smoke | 60 s |
| Docker integration (`ssh-replacement`) | 600 s |
| Docker Compose gates (`pi-linux-integration`, `pi-linux-ssh-verify`) | 1500 s |
| docx check | 120 s |

## Workflow rules

- Order: functionality first > Windows tests > Linux tests > full suite.
- Test the feature being changed; full suite only when requested.
- Always ask before running `tests/docx`.
- Linux cycle (3.4): copy latest package into the container → run
  `pi -p /aftc-install` as user `pi` → only then Linux tests; a Linux
  failure is fixed on Windows first, re-verified, then the cycle repeats.
- Never push container state/credentials to any registry.
