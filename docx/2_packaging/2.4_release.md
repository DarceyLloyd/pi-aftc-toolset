## Function

The maintainer tooling at the repo root. Not shipped to users (npmignored
where relevant); no CI pipeline, no Docker in the release path. **npm
publishing is NEVER automated and never part of the release steps** — the
maintainer publishes to npm manually (the `publish.bat` script and the npm
token were removed from the repo 2026-08).

## Scripts

| Script | Invocation | Behaviour |
| --- | --- | --- |
| `shipit.ps1` | `.\shipit.ps1 [loop] [MinMinutes=25] [MaxMinutes=45]` | Ship helper: `git add -A` → commit `v<version>` (skip when clean) → `git push origin HEAD` → `gh release create v<ver> --title v<ver>` (skips when the release exists). Does NOT publish to npm — that is the maintainer's manual step. `loop` mode: repeats forever — waits a random 25–45 min (any key ships now, Ctrl+C exits), bumps the patch version, ships again. |
| `backup.ps1` | `.\backup.ps1 [Message]` | WinRAR backup of the repo into `.bak/<yyMMdd-HHmmss> (<message>).rar` (max compression, recursive, skips `.bak`, tests the archive). Requires WinRAR at `C:\Program Files\WinRAR\Rar.exe`. |
| `clear-docker.bat` | `clear-docker.bat` (no args) | Test-hygiene: removes ALL Docker containers, then the test images/networks used by the SSH + Linux gate suites. Refuses arguments; needs Docker installed. |

## Release discipline (AGENTS.md, normative)

- Versioning `major.minor.patch` (AGENTS.md normative): patch = any fix or
  change to an EXISTING feature, including new commands/options added to it
  (a new `/codex-*` command is a codex change → patch); minor = brand-new
  feature NOT part of an existing feature (new capability area, eg `/docx`
  when added) — an existing feature only gets a minor when it is heavily
  re-written; major = package-wide overhaul. Read the version from
  `package.json` — never invent it.
- Codex seed change ⇒ bump `codexVersion` in `data/extension-config.json`
  in the SAME release (2.1).
- Changelog: `change-log.txt` under `Updates v<major>.<minor>.x`, newest
  first, short user-facing summaries.
- "Ship it" / "push it up to github" / "release it" = the full flow:
  changelog entry → tests green (Windows first, Linux gates) → commit +
  push → `gh release create vX.X.X` (notes = changelog entry). Then the
  MAINTAINER publishes to npm manually — the AI never attempts `npm
  publish` (see AGENTS.md Shipping section).
- npm credentials live only with the maintainer (granular access token with
  publish permission + bypass-2FA). No token file, `.env` or publish
  script exists in the repo.

## States / failure modes

- git push / gh failures throw and stop shipit.ps1.
- npm publishing is a manual maintainer step outside these scripts.
