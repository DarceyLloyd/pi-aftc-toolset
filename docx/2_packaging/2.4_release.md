## Function

The maintainer tooling at the repo root. Not shipped to users (npmignored
where relevant); no CI pipeline, no Docker in the release path.

## Scripts

| Script | Invocation | Behaviour |
| --- | --- | --- |
| `publish.bat` | `publish.bat` | Publishes to npmjs.com with a LOCAL token. Reads `.env` at the repo root (one line: raw token or `NPM_TOKEN=<token>`; falls back to `.npm-token`), writes it into a TEMP `.npmrc` via `NPM_CONFIG_USERCONFIG` (deletes it after), never touches global/project npmrc. Token = npmjs granular access token with publish permission for pi-aftc-toolset + bypass-2FA. |
| `shipit.ps1` | `.\shipit.ps1 [loop] [MinMinutes=25] [MaxMinutes=45]` | Full ship: `git add -A` → commit `v<version>` (skip when clean) → `git push origin HEAD` → `gh release create v<ver> --title v<ver>` (skips when the release exists) → `publish.bat` → prints live npm version. `loop` mode: repeats forever — waits a random 25–45 min (any key ships now, Ctrl+C exits), bumps the patch version, ships again. |
| `backup.ps1` | `.\backup.ps1 [Message]` | WinRAR backup of the repo into `.bak/<yyMMdd-HHmmss> (<message>).rar` (max compression, recursive, skips `.bak`, tests the archive). Requires WinRAR at `C:\Program Files\WinRAR\Rar.exe`. |
| `clear-docker.bat` | `clear-docker.bat` (no args) | Test-hygiene: removes ALL Docker containers, then the test images/networks used by the SSH + Linux gate suites (3.3/3.4). Refuses arguments; needs Docker installed. |

## Release discipline (AGENTS.md, normative)

- Versioning `major.minor.patch` (AGENTS.md normative): patch = any fix or
  change to an EXISTING feature, including new commands/options added to it
  (a new `/codex-*` command is a codex change → patch); minor = brand-new
  feature NOT part of an existing feature (new capability area, eg `/docx`
  when added) — an existing feature only gets a minor when it is heavily
  re-written; major = package-wide overhaul. Read the version from
  `package.json` — never invent it.
- Codex seed change ⇒ bump `codexVersion` in `data/extension-config.json`
  in the SAME release (2.1).
- Changelog: `change-log.txt` under `Updates v<major>.<minor>.x`, newest
  first, short user-facing summaries.
- "Ship it" / "push it up to github" / "release it" = the full flow:
  changelog entry → tests green (Windows first, Linux gates) → commit +
  push → `gh release create vX.X.X` (notes = changelog entry) →
  `publish.bat` → verify `npm view pi-aftc-toolset version`.
- `.env` is gitignored AND npmignored — never committed, never shipped.

## States / failure modes

- publish without `.env`/`.npm-token` → hard error with setup hint.
- git push / gh / npm failures throw and stop shipit.ps1.
