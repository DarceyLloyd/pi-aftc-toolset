## Function

where relevant); no CI pipeline, no Docker in the release path.

## Scripts

| Script | Invocation | Behaviour |
| --- | --- | --- |
| `ship-it.bat` | `ship-it.bat` (no args) | THE minimal ship flow: reads the version from `package.json`, `git add -A` → commit `v<version>` (skipped when clean) → `git push` → `gh release create v<ver> --title v<ver>` (no notes; skipped when the release exists). No descriptions, no bumping. |
| `shipit.ps1` | `.\shipit.ps1 [loop] [MinMinutes=25] [MaxMinutes=45]` | Ship helper (superseded by `ship-it.bat` for one-shot use): `git add -A` → commit `v<version>` (skip when clean) → `git push origin HEAD` → `gh release create v<ver> --title v<ver>` (skips when the release exists). `loop` mode: repeats forever — waits a random 25–45 min (any key ships now, Ctrl+C exits), bumps the patch version, ships again. |
| `backup.ps1` | `.\backup.ps1 [Message]` | WinRAR backup of the repo into `.bak/<yyMMdd-HHmmss> (<message>).rar` (max compression, recursive, skips `.bak`, tests the archive). Requires WinRAR at `C:\Program Files\WinRAR\Rar.exe`. |
| `clear-docker.bat` | `clear-docker.bat` (no args) | Test-hygiene: removes ALL Docker containers, then the test images/networks used by the SSH + Linux gate suites. Refuses arguments; needs Docker installed. |

## Release discipline (AGENTS.md, normative)

- Versioning `major.minor.patch` (AGENTS.md normative): patch = any fix or
  change to an EXISTING feature, including new commands/options added to it
  (a new `/codex-*` command is a codex change → patch); minor = brand-new
  feature NOT part of an existing feature (new capability area, eg `/docx`
  when added) — an existing feature only gets a minor when it is heavily
  re-written; major = package-wide overhaul. Read the version from
  `package.json` — never invent it.
- Codex seed change ⇒ bump `codexVersion` in `data/extension-config.json`
  in the SAME release (2.1).
- "Ship it" / "push it up to github" / "release it" / "ship vX.X.X" = run
  `ship-it.bat` (the AI does exactly this - one run, no checklist): the bat
  reads the version from `package.json` (never invented), commits `vX.X.X`,
  pushes and creates `gh release create vX.X.X --title vX.X.X` (no notes). No
  tests run by the flow, no descriptions (see AGENTS.md
  Shipping section).

## States / failure modes

- git push / gh failures throw and stop the ship scripts.
