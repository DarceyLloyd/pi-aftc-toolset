## Purpose

**Owns:** the codex knowledge base lifecycle — seed, inject, detect, load, learn, version-guard.
**Does not own:** the shipped seed assets themselves (2), the skills (3).
**Depends on:** 1.1, 1.2, 1.3. **Dependents:** none (model-facing feature).

## Public API & contracts

Commands: `/aftc-codex` (menu; alias `/codex`), `/codex-enable`, `/codex-disable`, `/codex-init`, `/codex-refresh`, `/codex-install`, `/codex-learn`, `/codex-status`, `/codex-inject-rules` (per-session rules-only mode). Model tools: `codex_load(topic)`, `codex_add_entry`, `codex_edit_entry`, `codex_remove_entry`.

## Internal architecture & data flow

Coordinator pattern (1.7.1 wires 1.7.2–1.7.9; sub-modules import types only from the coordinator, never each other). Two-copy data model: the shipped seed (`data/aftc-codex/`) is copied one-way to the live dir (`<dataDir>/aftc-codex/`) on first enable; the live copy is never auto-overwritten. Injection is hybrid: stable rules/guidance/resource-list ride the cached system-prompt prefix via `before_agent_start` (byte-stable files, cache-friendly); a lightweight marker message lives in history; the `context` event prunes older codex docs/markers as matched tool_use+tool_result pairs (non-destructive). Durable per-session state (`prepped`/`silent`) rides `appendEntry("aftc-codex-state")`. The version guard (1.7.7) pauses injection/loads on a seed/live version mismatch; with `aftcCodexAutoSync` (default ON) the startup auto-sync (1.7.1) usually merges the new shipped content into the live copy non-destructively before the user ever sees that state — manual fallback `/codex-sync`, destructive alternative `/codex-install` (wipe + fresh seed).

Production-safety invariants: never destroy user data, never break a session, fail soft, off by default, idempotent, copy-only seeding, byte-stable list generation.

## Configuration

`aftcCodexEnabled` (false), `aftcCodexInjectGuidance` (true), `aftcCodexAutoLoad` (true), `aftcCodexSeeded` (false), `aftcCodexAutoAddEntries` (true), `aftcCodexAutoSync` (true), `aftcCodexVersion` (0 = pre-versioning).

## Setup, seeding & first run

`/codex-enable` seeds on first use (choice in TUI), then `/codex-init` preps a session.

## Testing

`tests/aftc-codex-check`, `aftc-codex-status-check`, `codex-compat-check`, `codex-detect-check`, `codex-entries-check`, `codex-seed-to-live-check`, `aftc-codex-integration` (3 suites).

## Operational notes & known limitations

- ~29KB prefix injection — warns cost-sensitive users (README quick-links warning).
- Rules-only mode (`/codex-inject-rules`) is per-session state, survives `/reload`, cleared by `/new`; init/refresh/learn refuse while it is active.
