# 1.8 - docx Generator

The `/docx` project documentation generator: backs up existing docs, injects the guide's execution prompt, and lets the model regenerate the full documentation set.

## Purpose

**Owns:** the `/docx` feature end-to-end — confirmations, backup, prompt assembly, and the scripts the model runs mid-generation.
**Does not own:** the generated output (belongs to the user's project).
**Depends on:** 1.1, 1.3, adm-zip (zip script). **Dependents:** none.

## Public API & contracts

`/docx [--yes]`. `--yes` skips both modals (headless). Help-registry category General.

## Internal architecture & data flow

Flow: context gates (`ctx.getContextUsage().percent` >= 50 → flat-out refuse, full-screen info modal in the TUI / warning line headless, applies even with `--yes`; >= 20 → advisory modal recommending `/new` first) → main confirm modal (backup warning + long-wait expectation) → deterministic backup (1.8.2) → execution prompt extracted from the shipped guide's section 18 and injected via `pi.sendUserMessage` with `[PROJECT_PATH]`/script paths substituted. In print/headless mode the command holds itself open (poll for turn start, then `ctx.waitForIdle()`) because `sendUserMessage` is fire-and-forget and print mode exits when the command returns. The model generates the docs, then runs the shipped scripts: map-scan (step 1), link-audit (step 11, loops until PASS), zip-old (final action: `docx/old_docs/` → `docx/old_docs.zip`, folder removed).

## Configuration

None (a slash command is opt-in by nature).

## Setup, seeding & first run

Nothing; adm-zip arrives via `/aftc-install` (npm install).

## Testing

`tests/docx/docx-check.mjs` (72 checks: backup rules, re-run fold-in, first-run, leftovers, link-audit pass/fail incl. `_sitemap`/`_design` partners, zip-old, command end-to-end with mock pi, map-scan fixture). Live generation quality is evaluated manually against the five real project fixtures kept in `tests/docx/` (Electron voice-to-CLI app, Java desktop app, Docker web stack, WebGPU template, JUCE VST3 plugin): run `/docx --yes` in each and review the output against the guide (sitemaps, design docs, region breakdowns, container docs).

## Operational notes & known limitations

- Destructive-adjacent by design: old docs end up zipped; the modal tells the user to make their own backup first.
- Backup scope is a whitelist (root + `./docs/` + previous `docx/`), so framework/sub-project docs are structurally unreachable.
