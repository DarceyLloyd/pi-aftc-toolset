## Purpose

**Owns:** the mapping of carrier session ids to saved connection names, the selected session for local commands, credential clearing after auth, and bounded command/transfer results.
**Does not own:** the wire protocol (1.6.3), persistence (1.6.5).
**Depends on:** 1.6.3, 1.6.5, 1.6.7. **Dependents:** 1.6.1.

## Public API & contracts

Session-facing methods used by 1.6.1: connect by saved name (idempotent), disconnect by opaque id, run command (bounded stdout/stderr/exit-code/truncation), PTY open/send/peek/resize/interrupt/close, SFTP up/download, remote file ops. `getStatus()` returns `{ connected, carrierState, sessions }` — the single source for `/ssh-status` and `ssh_status`.

## Internal architecture & data flow

Each session is an entry `{ opaqueId, savedName, carrierSessionId }`. Credentials arrive from the connection form, are passed to the carrier for ONE auth attempt (including the host-key-approval retry), then cleared from memory. On carrier termination all sessions are cleared (no stale state). Output passes through redaction before leaving this layer.

## Configuration

None (session state is in-memory; durable data lives in ssh.json, 1.6.5).

## Setup, seeding & first run

Nothing.

## Testing

`tests/ssh-connect-headless-check`, `ssh-idle-connection-lost-check` (monitor prunes dropped sessions), `ssh-local-path-check`.

## Operational notes & known limitations

- Sessions are per-pi-process; a pi restart drops them (reconnect by name).
- Bounded results protect the model context; full output is never streamed to the model.
