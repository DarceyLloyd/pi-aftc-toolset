## Purpose

**Owns:** what codex content reaches the model and when — the cached-prefix block, the in-history marker, pruning, fresh-session notice/auto-prep, rules-only mode.
**Does not own:** file storage (1.7.2), detection (1.7.4).
**Depends on:** 1.7.2, 1.7.4, 1.7.7. **Dependents:** none.

## Public API & contracts

`before_agent_start` returns `{ systemPrompt: event.systemPrompt + block }` when `enabled && prepped && !silent && compat-safe`. The block = codex-rules.md + (optional) thought-and-action-guidance.md + codex-resource-list.md + a fetch instruction. Rules-only mode (`/codex-inject-rules`) injects ONLY the `## Critical Global Rules` section extracted from the rules file — no gates, no marker, no ceremony.

## Internal architecture & data flow

Prefix files are read fresh from disk each turn and are byte-stable (the list regenerates only on content change) so provider prompt caches hit every turn after the first. The marker message (`aftc-codex-marker`, display via `registerMessageRenderer`) carries detected topics (1.7.4) when auto-load is on. The `context` handler prunes older codex docs as matched tool_use+tool_result pairs (never orphaning a tool_use) and drops emptied assistant messages; when disabled/silent it strips ALL codex content. Fresh-vs-resume uses `session_start.reason`; the fresh-session notice is a durable entry (`aftc-codex-prep-notice`) with a `registerEntryRenderer` — no timers. Per-session state persists via `appendEntry("aftc-codex-state")`.

## Configuration

## Setup, seeding & first run
