## Purpose

**Owns:** detecting that the live codex is behind the shipped seed and pausing codex features until the user reinstalls.
**Does not own:** the reinstall itself (1.7.8's `/codex-install`).
**Depends on:** 1.2 (config), 2 (shipped `extension-config.json`). **Dependents:** every codex feature (via `ctx.checkCompat()`).

## Public API & contracts

`checkCodexCompatibility() -> { isSafe: boolean; message: string }` — pure TS, fresh disk reads (the shipped file is read directly, never cached; the live version is the `aftcCodexVersion` preference, default 0).

## Internal architecture & data flow

Mismatch => `isSafe: false`: `before_agent_start` injection and `codex_load` pause (an out-of-date copy is never injected/served), `/aftc-codex-*` commands show the message and refuse — EXCEPT `/codex-install` (the fix), `/codex-disable` and `/codex-status`. On mismatch `/codex-install` wipes + re-seeds with NO confirmation (the guard has been telling the user to run exactly that command — typing it is the confirmation); when versions MATCH it is a confirmed destructive re-install. A missing/unreadable seed version disables all version logic (fail-soft: never wipes when unsure). The fresh-session notice gains a NOTICE line from the same guard.

## Configuration

`aftcCodexVersion` (live side; set by the seed on install). Shipped side: `codexVersion` in `extension-config.json` — **must be bumped by the maintainer in any release whose seed changed** (AGENTS.md release rule), or users never see the notice.

## Setup, seeding & first run

Nothing.

## Testing

`tests/codex-compat-check` (11 checks: missing/malformed shipped file, fresh reads, mismatch matrix).

## Operational notes & known limitations

- The wipe loses live-only learned entries; only maintainer-synced (live→seed) entries survive a release.
