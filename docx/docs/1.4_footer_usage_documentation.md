## Purpose

**Owns:** session telemetry (tokens, cache, cost, timing), the `turns.db` store (`turns` + `tasks` tables), provider allowance polling, and the rendered outputs (footer widget, `/usage-report` HTML).
**Does not own:** SSH/notify usage of events, the config store (1.2).
**Depends on:** 1.1, 1.2 (db, config, types). **Dependents:** none (leaf feature).

## Public API & contracts

- `core.ts` — `createCore(pi, recorder, allowance) -> FooterDataProvider`: session stats, timeframe aggregates, `onTick()`.
- `footer-widget.ts` — `createFooterWidget(pi, data)`: 4-5 line widget below the editor via `ctx.ui.setWidget`; 1Hz ticker; `/aftc-footer` menu (Enable footer, Show recorded averages, Set averages timeframe — 19 rolling/calendar windows).
- `usage-recording.ts` — `createUsageRecording(pi)`: records turns/tasks into SQLite.
- `usage-report.ts` — `/usage-report` (generates + opens `report.html`: Overview / Models / Thinking / Timings / Projections tabs), `/usage-clear` (drops both tables).
- `allowance.ts` — `createAllowance(pi)`: line-5 quota (5h/weekly) for providers with usage endpoints (ChatGPT/Codex OAuth, MiniMax, Z.ai, Kimi, Anthropic OAuth).

## Internal architecture & data flow

Event-driven: `message_end` tracks assistant usage + stopReason; `agent_settled` finalises a task. Task time = wall-clock user-enter → agent-settled; failed/aborted tasks are recorded but never averaged (`stop_reason = 'complete'` only). The widget re-renders at 1Hz (`tui.requestRender()`), timeframe aggregates refresh at most every 10s; the active component is tracked at module scope so `/aftc-footer` hide and `session_shutdown` dispose the ticker (no leaked 1Hz timers). The report is a self-contained HTML file (embedded CSS/JSON/JS; only external ref is a pinned Chart.js CDN — offline degrades to text).

Money formatting rules (`fmtMoney`): `$0.00`; 4dp below $1; 2dp below $1,000; whole numbers with thousands separators at $1,000+ — everywhere, client and server formatters kept in sync. Durations: `Xh Ym Zs`, omit zero leading units.

## Configuration

`footerEnabled` (true), `footerAveragesEnabled` (true), `footerTimeframe` (`"3d"`; rolling `1h`..`72h`, date-based `1d`..`1y`; legacy values migrated).

## Setup, seeding & first run

Requires `better-sqlite3` (`/aftc-install`); without the native module the footer lines 1-3 still render and recording/reporting no-op with a log line.

## Testing

`tests/footer-widget-check`, `footer-task-time-check`, `footer-timeframe-check`, `allowance-check`, `usage-report-check`, `data-migration-check`.

## Operational notes & known limitations

- Burn rates ($/hr, $/min) are session-scoped; line 4 is the long-term window.
- Allowance line hides silently for unsupported providers or endpoint failure.
