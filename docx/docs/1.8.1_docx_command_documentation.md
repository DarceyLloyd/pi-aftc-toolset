## Internal architecture & data flow

1. `--yes` or modals: context gate first (`ctx.getContextUsage()` + `ctx.model.contextWindow` for the message), then the main confirm (both via `showConfirm`; safe option default).
2. `runDocxBackup(ctx.cwd)`; ANY error aborts before the model is engaged (the guide's STOP rule).
3. `buildDocxPrompt`: reads `documentation_guide.md` fresh from disk (never cached), extracts the section-18 ` ```text ` block, substitutes `[PROJECT_PATH]`, `[GUIDE_PATH]`, `[MAP_SCAN_PATH]`, `[LINK_AUDIT_PATH]`, `[ZIP_OLD_PATH]` (forward-slash absolute paths), prepends a backup summary (moved/copied counts, partner skips, leftovers, first-run).
4. Injection: `pi.sendUserMessage(prompt)` idle, `deliverAs: "followUp"` busy. **Print/headless**: poll `ctx.isIdle()` until the turn starts (≤10s), then `await ctx.waitForIdle()` — without this the process exits before the generation turn runs.

Failure behaviour: backup destination uncreatable / move errors / count mismatch → `aftcConsole.error` and no prompt; missing/malformed guide → error (backup still restorable from `docx/old_docs/`).
