## Purpose

**Owns:** resource-list regeneration, entry-ID backfill, and the maintainer-only live→seed release sync.
**Does not own:** runtime behaviour (spawned on demand, never long-running).
**Depends on:** the live/seed layout (1.7.2). **Dependents:** 1.7.2 (spawns), the maintainer (manual).

## Public API & contracts

- `sync-codex-resources.mjs` — regenerates `codex-resource-list.md` from the live resources. **Byte-stable** (cache-critical): deterministic code-unit sort, no timestamps, atomic write, skipped when unchanged, never throws. Spawned by resource-touching commands and internally by `codex_add_entry` on topic creation.
- `ensure-entry-ids.mjs` — ensures every entry has a unique 6-char `[ID]`; idempotent; backstop for hand-edits (the entry tools generate IDs themselves).
- `live-to-seed-sync.mjs` — maintainer-only release tool (dev-gated: run via
  `/codex-live-to-seed [--apply]` in the dev checkout, or by hand): dry-run by
  default, `--apply` writes; ports live-only entries (keyed by `[ID]`) and new
  topics into the package seed; same-ID text differences are reported as
  conflicts, never auto-overwritten; the generated list is never copied.
  Honours `AFTC_TOOLSET_DATA_ROOT`.

## Internal architecture & data flow

Plain Node ESM, arg arrays, self-terminating. Spawned from the extension with `process.execPath` fallback.

## Operational notes & known limitations

- After a live→seed sync, bump `codexVersion` (1.7.7) in the same release or users never receive the new content.
