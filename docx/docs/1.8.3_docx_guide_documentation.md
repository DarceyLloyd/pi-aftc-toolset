## Purpose

**Owns:** the normative rules for generated documentation — architecture, structure-map rules, naming/titles, per-doc-type templates, UI-surface mapping (sitemaps, per-area design docs, single-surface breakdown), sub-projects, containers, dev tooling, exclusions, cross-references, backup contract, the section-18 execution prompt, the pre-launch checklist.
**Does not own:** any runtime code.
**Depends on:** nothing. **Dependents:** 1.8.1 (extracts section 18), the model (follows it during generation).

## Public API & contracts

A markdown spec, audience "AI models only". Section 18 is a fenced ` ```text ` block with placeholders (`[PROJECT_PATH]`, `[GUIDE_PATH]`, `[MAP_SCAN_PATH]`, `[LINK_AUDIT_PATH]`, `[ZIP_OLD_PATH]`) that 1.8.1 substitutes at runtime.

## Internal architecture & data flow

Adapted from the maintainer's source guide for the `/docx` layout: output in `./docx/` (master + map + `docs/` tree), root `README.md` generated LAST (evaluating the old README from the backup), `AGENTS.md` edited in place via the managed `AFTC-DOCX` block, backup/zip owned by tooling, `docx/` contains exactly `project_documentation.md` + `project_map.md` + `docs/` (files only, no subfolders — sub-maps are `<id>_<area>_map.md` FILES in `docs/`). It also carries shipped-only normative content the maintainer's source guide lacks: platform-neutral UI-surface mapping, mandatory per-UI-branch sitemaps, global/per-area design-rules docs, and the single-surface breakdown rule (sections 3/5/6/9/14/17/18/19).
