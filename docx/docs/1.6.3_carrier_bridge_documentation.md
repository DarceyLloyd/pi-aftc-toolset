## Purpose

**Owns:** the carrier process lifecycle (idle → ready → terminated) and the JSON-RPC 2.0 client protocol over stdin/stdout.
**Does not own:** SSH semantics (1.6.4), session bookkeeping (1.6.2).
**Depends on:** 1.1 (child_process), 1.2 (paths). **Dependents:** 1.6.2.

## Public API & contracts

Start (lazy, first use), `request(method, params)`, `stop()`, `reset()` (required after `terminated`). States: `idle`, `starting`, `ready`, `terminated`. Spawn uses `node:child_process` argument arrays with no shell; `uv.exe` on Windows, `uv` elsewhere; runs `uv sync --locked` against the packaged carrier (`carrier/pyproject.toml`) then launches `aftc_ssh_carrier.__main__`.

## Internal architecture & data flow

One JSON-RPC request per line on stdin, one response per line on stdout; a ready handshake (`ping`) gates `ready`. When the last session disconnects a 30s grace timer stops the carrier. Orphan prevention: the child self-exits on stdin EOF (pi crash) and an idle watchdog (default 10min, `AFTC_SSH_IDLE_TIMEOUT_SEC`) is the last resort. Unexpected exit => `terminated`: all requests rejected, never a silent restart — the caller must `reset()`.

## Configuration

`AFTC_SSH_IDLE_TIMEOUT_SEC` (carrier idle self-exit, seconds).

## Setup, seeding & first run

`/aftc-install` performs the initial `uv sync --locked` and ready-check.

## Testing

`tests/ssh-carrier-check`, `ssh-carrier-ready-check`, `ssh-carrier-lifecycle-check`, `ssh-idle-self-exit-check`, `install-platform-uv-check`.

## Operational notes & known limitations

- One carrier per pi process; multi-session capable.
- No listening sockets, no HTTP — stdio only (attack-surface choice).
