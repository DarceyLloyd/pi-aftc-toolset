## Purpose

**Owns:** the user surface — enable/disable/init/refresh/install/learn/status commands, `/codex-inject-rules`, and the `/aftc-codex` settings menu.
**Does not own:** the mechanics (1.7.2–1.7.7).
**Depends on:** all codex sub-modules, 1.3 (menu/dialogs). **Dependents:** none.

## Public API & contracts

Commands and aliases per the master table (1.7), plus the dev-gated
maintainer command `/codex-live-to-seed [--apply]` (dry run in a viewer,
confirm, then apply; refuses outside the dev checkout where the `.dev`
marker is absent). Menu rows: Codex Enabled (Yes/No), Inject Thought Guidance (Yes/No), Auto-Detect & Load Docs (Yes/No), Auto Sync Codex Update on Startup (Yes/No), Resources & Updates (Start Fresh — confirmed destructive; Open Codex Resource Dir). Body: `AFTC Codex: <N> resources available` + the session state (Prepped / Not prepped (Run /codex-init to prep the AI) / Rules-only). Inline toggles re-render with the selection preserved. There is no in-menu help viewer — the README is the help surface.

## Internal architecture & data flow

Resource-touching commands (-learn, -install, -init, -refresh, Start Fresh) spawn the list-regeneration script first (via 1.7.2); pure toggles skip it. `/codex-status` renders a colored status entry (enabled, embedded, files read). `/codex-inject-rules` sets per-session rules-only state on the durable codex-state entry; init/refresh/learn refuse with a warning while it is active; `/new` clears it.

## Configuration

Writes the `aftcCodex*` preferences via 1.2 (fresh read-modify-write).

## Setup, seeding & first run

`/codex-enable` offers the first-run seed choice in the TUI.

## Testing

`tests/aftc-codex-check` (commands + menu + rules-only), `aftc-codex-status-check`.

## Operational notes & known limitations

- The compat guard (1.7.7) shows its message in an aftc-ui modal and refuses all commands except install/disable/status.
