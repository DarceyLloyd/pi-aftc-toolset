## Purpose

**Owns:** the redaction boundary — registering active connection metadata (host, user, port, paths, saved passwords) as redaction values and filtering all carrier output through it.
**Does not own:** connection lifecycle (1.6.2).
**Depends on:** nothing (pure string filtering). **Dependents:** 1.6.2 (applies it to all output).

## Public API & contracts

Register/unregister redaction values on connect/disconnect; `redact(text)` applied to command output, file content, and carrier errors before they reach the model or TUI display.

## Internal architecture & data flow

VERBATIM case-sensitive exact-substring matching — a deliberate safety-first choice (documented trade-off): a saved value that is a common word (user `admin`, host `mail`) is redacted EVERYWHERE, including innocent text (`administrator` -> `[redacted]istrator`). The mitigation is memorable-but-unique saved values. The boundary survives rename/removal and is cleared on disconnect.

## Operational notes & known limitations

- Over-redaction is expected and accepted; under-redaction is a bug.
- Redaction is a guard, not a parser — it never tries to understand output structure.
