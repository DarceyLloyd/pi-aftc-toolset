## Purpose

**Owns:** where codex files live (seed vs live), the seeding flow, resource file discovery/reads, and spawning the maintenance scripts.
**Does not own:** version policy (1.7.7), injection (1.7.3).
**Depends on:** 1.2 (paths). **Dependents:** 1.7.1, 1.7.3, 1.7.6, 1.7.8.

## Public API & contracts

Resource reads by topic (searches every category folder + top-level, folder is organisation only), category listing, `isSeeded()`, seed/re-seed (copy-only for learned content: existing live `resources/` files are never overwritten), and `runSyncScript()` (child_process arg arrays, no shell, falls back to `process.execPath`).

## Internal architecture & data flow

Seed: `extensions/aftc-toolset/data/aftc-codex/` (rules, guidance, markdown guidance, resources/<category>/*.md). Live: `<dataDir>/aftc-codex/` plus the GENERATED `codex-resource-list.md` (never shipped). One-way flow seed → live; a full refresh only happens via Start Fresh / `/codex-install` (delete + full copy). All I/O is fail-soft.

## Configuration

Data-dir resolution per OS via 1.2 (`AFTC_TOOLSET_DATA_ROOT` override for tests).

## Setup, seeding & first run

First enable seeds the live copy (TUI offers the choice).

## Operational notes & known limitations

- The seed is SOURCE only: generated files (the resource list) must never be committed into it.
