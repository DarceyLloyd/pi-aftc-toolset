## Purpose

**Owns:** `CodexState` (prepped/silent/noticedThisSession), the `CodexContext` shared object, the read tracker (durable `aftc-codex-read` entries + per-session read set), and `codex_load`.
**Does not own:** injection (1.7.3), writes (1.7.6), commands (1.7.8).
**Depends on:** 1.7.2–1.7.8. **Dependents:** the sub-modules (type-only imports).

## Public API & contracts

`createAftcCodex(pi): void` (wired by index.ts). `codex_load(topic)`: searches all category folders + top-level; aliases `ts`/`py`/`js`/`pine`/`gd`; specials `rules`/`guidance`/`list`/`markdown`; strips a leading `@` and a trailing `.md`; supports `category/name`; empty resources return a fixed one-liner (and still count as a read); huge files truncate (`truncateTail`, 50KB/2000 lines) with the full path stated; unknown topics throw with the valid list; every read is tracked durably for `/codex-status`.

## Internal architecture & data flow

The read tracker dedupes durable read entries (`durableSeen`) and maintains `sessionReads`: cleared on fresh sessions, rebuilt from durable entries on resume/reload/fork — this is the read-before-write evidence for 1.7.6.
