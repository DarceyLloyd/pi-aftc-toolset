## Purpose

**Owns:** the SSH feature's pi surface — all `/ssh-*` commands and all `ssh_*` model tools, their help-registry entries, prompt snippets/guidelines, and output truncation.
**Does not own:** session mechanics (1.6.2), the carrier process (1.6.3), persistence (1.6.5).
**Depends on:** 1.6.2–1.6.7, 1.3, 1.1. **Dependents:** none (leaf).

## Public API & contracts

`createSshModule(pi): void` — wired by the orchestrator. Every model tool: has `promptSnippet`, names itself in `promptGuidelines`, strips a leading `@` from path args, truncates output (`truncateHead`/`truncateTail`), throws on error. Connection-level tools are ONLY `ssh_status` / `ssh_connect(name)` / `ssh_disconnect(id)` — the model can never create, edit, or delete connections.

## Internal architecture & data flow

Commands collect local input (forms/pickers from 1.6.6), then call into the session manager (1.6.2). Model tools resolve the opaque session id to the carrier session inside 1.6.2 and pass results through redaction (1.6.7) before returning. Destructive remote operations (write/mkdir/rename/remove/upload-overwrite) route through local confirmation overlays first.

## Operational notes & known limitations

- `ssh_connect` is idempotent by saved name (reconnect-safe).
- Command handlers guard dialogs with `ctx.hasUI`; headless use goes through the model tools.
