## Purpose

**Owns:** the instruction prompt that tells the model to persist durable, general lessons via the entry tools.
**Does not own:** the writes themselves (1.7.6 owns every mechanical step).
**Depends on:** 1.2 (config). **Dependents:** 1.7.8 (command wiring).

## Public API & contracts

`createCodexLearn(ctx) -> { buildLearnPrompt(), injectLearnPrompt(busy) }`. Injects as a user message (`deliverAs: "followUp"` when the agent is busy).

## Internal architecture & data flow

The prompt keeps only model judgement: review the session, route lessons to the right topic, codex_load first (the duplicate check AND the read-before-write allowance), classify (issue/rule/gotcha, first match wins), write with `codex_add_entry` (batched per topic), fix stale entries along the way. It carries the HARD LIMITS: a generality check (makes sense on ANY project? no project names/paths/URLs/project-invented terms — with a BAD/GOOD example pair) and the secrets ban (never passwords/keys/tokens — describe the shape, never a value), plus "a refusal means reword, never force it". Entries are always written directly with `codex_add_entry` (no propose-then-confirm mode — the write tools enforce format, uniqueness and safety).
