## Purpose

**Owns:** real SSH work — Paramiko connections, auth (password/key), host-key handling, PTY channels, SFTP, port forwarding, remote file ops.
**Does not own:** pi-side policy (sessions, redaction, confirmations) — it is a dumb executor behind JSON-RPC.
**Depends on:** paramiko >=3.4.0,<4.0.0; Python >=3.10. **Dependents:** 1.6.3.

## Public API & contracts

Entry point: `aftc_ssh_carrier.__main__:main` (project.scripts `aftc-ssh-sidecar`). JSON-RPC 2.0 over stdio: methods for connect/exec/pty/sftp/file ops; one request per line, one response per line. Multi-session: each connect returns a session id; PTY shells get shell ids.

## Internal architecture & data flow

Blocking Paramiko calls are wrapped per-request; PTY output is buffered for `peek`. Self-exit on stdin EOF (parent death) plus an idle watchdog (`AFTC_SSH_IDLE_TIMEOUT_SEC`, default 600s). Package layout: `pyproject.toml` (hatchling, wheel packages `src/aftc_ssh_carrier`), `scripts/` (carrier-side helpers), ruff config (line-length 120, py310).

## Configuration

- `requires-python >=3.10`; dev group: ruff >=0.6.0.
- Env: `AFTC_SSH_IDLE_TIMEOUT_SEC`.

## Setup, seeding & first run

`uv sync --locked` (run by `/aftc-install` or lazily by 1.6.3). Creates `carrier/.venv` — Linux/Windows-local, never commit (gitignored); never run host-side tools against a container-created venv (symlink EACCES lesson).

## Testing

Driven through the TS bridge: `tests/ssh-carrier-*`, and end-to-end via `tests/ssh-replacement` (Docker).

## Operational notes & known limitations

- Never silently restarted after a crash (1.6.3 owns that policy).
- Paramiko 4.x is pinned out intentionally (`<4.0.0`) — review before widening.
