## Purpose

**Owns:** auto-detection of project technologies for the marker message (`aftcCodexAutoLoad`).
**Does not own:** injection (1.7.3 consumes the result).
**Depends on:** 1.7.2 (resource existence for the topics/missing split). **Dependents:** 1.7.3.

## Public API & contracts

`detect(cwd) -> { topics: string[]; missing: string[] }` — `topics` have a live resource (loadable, named in the marker); `missing` are mapped but have no resource yet (named as bootstrap hints). Results are cached per cwd for the session.

## Internal architecture & data flow

Signals: file extensions (`.ts`→typescript, `.csproj`→blazor/dotnet-maui via content scan, ...), package.json deps/scripts/bin/engines (root parsed first, nested ones too), marker files (`Dockerfile`, `project.godot`, `deno.json`, `Cargo.toml`, ...), marker dirs, bounded content scan (≤64KB, ≤24 files), the `<!-- AFTC-CODEX-STACK topics: ... -->` block in auto-inject files (explicit pins, unioned — the ONLY detection path for design domains and target OS, and the way to pin stoplisted names), and a stoplisted whole-word keyword scan of AGENTS.md/CLAUDE.md/etc. Implied topics: design-* → design-common, mysql → database-common. Bounded walk: skips heavy dirs, caps depth 6 and 8000 files.
