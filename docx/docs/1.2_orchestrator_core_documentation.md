## Purpose

**Owns:** module lifecycle (one `createX(pi)` per feature), the live `config.json` preference store, all path truth (package root, persistent data dir), legacy data migration, and the shared better-sqlite3 connection.
**Does not own:** feature behaviour (1.4–1.11), UI primitives (1.3).
**Depends on:** 1.1. **Dependents:** every feature module.

## Public API & contracts

- `index.ts` — default extension factory; instantiates modules in order (aftcConsole.init first), wraps everything in try/catch that logs via `aftcConsole.log`.
- `paths.ts` — `getPackageRoot()` (walks up from `__dirname`, throws if the package shape is absent), `getPersistentRoot()`/`getDataDir()` (per-OS data dir, `AFTC_TOOLSET_DATA_ROOT` override), `migrateLegacyData()` (copy-forward from the pre-persistent package-local dir, idempotent, lock-safe).
- `config.ts` — `getPreference(key, default)` / `setPreference(key, value)`; `Preferences` interface + `DEFAULT_PREFERENCES` + the defaults-driven load-merge migration in `loadPreferencesInternal()`.
- `db.ts` — shared `better-sqlite3` connection to `turns.db`; fails soft (feature disabled with a log line when the native module is missing).
- `types.ts` — shared interfaces (`TurnRecord`, `FooterDataProvider`, ...).

## Internal architecture & data flow

Orchestrator pattern: features are self-contained modules that register their own commands/handlers; cross-module data flows only through the orchestrator (eg `createCore(pi, recorder, allowance)` returns a `FooterDataProvider` passed to `createFooterWidget`). **Config is never cached**: every `getPreference` re-reads the file; `setPreference` is a fresh read-modify-write with atomic tmp+rename writes; corrupt files return defaults and are never clobbered. Adding a preference = interface + `DEFAULT_PREFERENCES` (the load-merge backfills any missing/wrong-typed defaults key automatically; only a derived-not-default value like `notifyEnabled` needs a special case). Retiring a preference = remove from both + one line in `RETIRED_KEYS` (never pruned: strips must survive across many skipped releases; a leftover dead key is inert).

## Configuration

Live config: `<dataDir>/config.json` (Windows `%APPDATA%\pi-aftc-toolset\data\`). Every key, default and migration rule is tabulated in the old `docs/data-and-packaging.md` (backup) and enforced by `tests/config-fresh-read-check`. New user-facing features default to disabled.

## Setup, seeding & first run

`migrateLegacyData()` runs first inside the factory; `config.json` is created lazily from defaults on first access.

## Testing

`tests/config-fresh-read-check` (stale-cache regression: external edits visible immediately, migration write-back, corrupt-file handling), `tests/data-migration-check`.

## Operational notes & known limitations

- Two pi processes sharing one data dir = last-writer-wins per `setPreference` (best-effort, unsupported).
- `getPackageRoot()` throws when the package shape is missing — by design (a silent wrong root caused misleading errors historically).
