## Purpose

**Owns:** CRUD + persistence of saved connection metadata.
**Does not own:** live sessions (1.6.2), credential use (1.6.2 holds them for one auth attempt only).
**Depends on:** 1.2 (paths). **Dependents:** 1.6.1, 1.6.6.

## Public API & contracts

List/get/add/update/remove saved connections. Stored per connection: name, username, host, port, timeout, optional key path, optional saved password (user-approved), plus the auto-accept-host-keys toggle.

## Internal architecture & data flow

`ssh.json` lives in the persistent OS data dir (survives `pi update`), is never shipped, and is never exposed to the model — the store is read by the connection form/manager (local UI) and by connect-by-name. Writes are atomic (tmp + rename).

## Configuration

The file IS the configuration. Managed exclusively through `/ssh-cm`.

## Setup, seeding & first run

Created lazily on first save.

## Testing

`tests/ssh-connection-store-check`, `ssh-auto-accept-check` (toggle persistence).

## Operational notes & known limitations

- Saved passwords are covered by the redaction layer (1.6.7) wherever they could appear in output.
- The store holds metadata, not sessions — a pi restart loses sessions but never connections.
