## Purpose

**Owns:** `play_sound-win-x64.exe`, `play_sound-linux-x64`, `play_sound-macos-x64`, `play_sound-macos-arm64`, and `bin/src/` (miniaudio-based C source, MIT-0 — zero distribution obligations).
**Does not own:** when sounds play (1.5 notify) or the MP3 assets (2).
**Depends on:** nothing at runtime. **Dependents:** 1.5 (notify).

## Public API & contracts

Invoked as `play_sound-<platform> <audioFilePath>`; plays the file and exits.

## Internal architecture & data flow

Spawned detached by notify: `spawn(bin, [path], { detached: true, stdio: "ignore", windowsHide: true }); child.unref();` — fire-and-forget, never blocks pi, errors logged and swallowed. Preview playback kills the previous preview child before starting the next.

## Configuration

None.

## Setup, seeding & first run

Ships in the package; no build needed (prebuilt per platform). Rebuild from `bin/src/` only when the player itself changes.

## Testing

Covered indirectly by `tests/notify-check` (playback is mocked/injected there).

## Operational notes & known limitations

- No volume control or stop API — previews are stopped by killing the child.
