## Purpose

**Owns:** every interactive screen (menus, confirms, forms, inputs, viewers) and every transcript/diagnostic line the toolset writes.
**Does not own:** feature logic, SSH terminal UI (1.6.6 uses its own full-screen components built on the same primitives).
**Depends on:** 1.1 (pi-tui components, theme). **Dependents:** all UI-producing features (1.5, 1.6, 1.7.8, 1.8.1).

## Public API & contracts

`ui/aftc-ui.ts`:
- `showMenu(ctx, { title, items, initialIndex, body, help, fullscreen, onHighlight, labelWidth }) -> string | null`
- `showConfirm(ctx, { title, body, yesLabel, noLabel }) -> boolean` (safe option highlighted first)
- `showForm(ctx, { title, fields, validate, submitLabel }) -> Record | null` (string/int/float/choice/password, required)
- `showInput` / `showIntInput` / `showFloatInput`, `showViewer(ctx, { title, lines | rows })`
- `AftcUi` class: `panelTop/panelBottom/panelRow/menuRow/fieldLabel/inputRow`, `panelWidth()`, `listViewport()`, `takeover()`.

`ui/aftc-console.ts`:
- `aftcConsole.init(pi)` once per session (index.ts only); `emphasis(ctx, text)` (accent entry via `appendEntry` + `registerEntryRenderer`, display-only), `warn`, `error`, `info` (over `ctx.ui.notify`). Stdout side: `log(text)` (debug chatter — stdout echo gated by `debugLoggingEnabled`, ALWAYS captured in `<dataDir>/debug.log`), `logError(text)` (failures — never gated, always stdout + file), `print(text)` (headless command responses — never gated, not filed). debug.log rotates to debug.log.old past 5MB.

## Internal architecture & data flow

aftc-ui renders GRUB-style full-screen takeovers (black bg, `#555555` borders, `#fca02f` titles, `#2d1d08` selection bar) via `ctx.ui.custom(..., { overlay: true })`. Binding rules: never embed values in labels (aligned value column via `labelWidth` + ` | ` description); pickers mark the effective row `(current)` and pre-select with `initialIndex`; menus preserve the highlighted row across in-place re-renders. Non-TUI guards: menus/forms/inputs resolve null, confirm falls back to `ctx.ui.confirm`, viewer prints lines.

aftc-console exists because `ctx.ui.notify` has no accent severity; `emphasis` renders an accent-coloured custom entry (`aftc-console-emphasis`) that never enters LLM context. Registration is fail-soft when `registerEntryRenderer` is unavailable.

## Configuration

None.

## Setup, seeding & first run

Nothing to set up; `init(pi)` is called by the orchestrator.

## Testing

`tests/aftc-ui-check` drives overlay components headlessly via `handleInput`.

## Operational notes & known limitations

- Exactly one visibly active element per screen; Escape cancels everywhere.
- Custom screens compose ONLY the exported primitives — feature modules never hand-build chrome.
