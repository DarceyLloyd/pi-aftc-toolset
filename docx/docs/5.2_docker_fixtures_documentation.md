Compose service names: `ssh-test-server` (ssh-replacement), `pi-linux` (pi-linux-integration), `pi-client` + `ssh-target` (pi-linux-ssh-verify). The `install-test` fixture is an image-only Dockerfile.

## Purpose

**Owns:** end-to-end proof that SSH and the extension install work on real Linux — commands, SFTP, port forwarding, PTY, and a live model prompt.
**Does not own:** local suites (5.1).
**Depends on:** Docker Desktop. **Dependents:** the release workflow (6).

## Public API & contracts

- `tests/ssh-replacement/` — `docker-compose.yml` + `Dockerfile` + `web-fixture/`: an Ubuntu SSH server (password + disposable key auth). Driver env: `SSH_TEST_HOST/PORT/PASSWORD/IDENTITY_FILE`, `SSH_TEST_EXISTING_FIXTURE`.
- `tests/pi-linux-integration/` — Debian + Node 22 + pi + uv; package copied to `/opt/pi-aftc-toolset`; runs `/aftc-install`, the installer/SSH/carrier/npm/docx suites inside the container, the SSH smoke against the fixture, and a live prompt. 1500s watchdog.
- `tests/pi-linux-ssh-verify/` — two-container verification without provider allowance.
- `tests/install-test/Dockerfile` — minimal install verification image.

## Internal architecture & data flow

Verification cycle (binding): copy latest package → run `pi -p /aftc-install` as user `pi` → check exit status → run Linux tests; a Linux failure is fixed on Windows, verified on Windows, then the cycle restarts. Disposable auth: the local pi `auth.json` is copied in for the live prompt and removed with the container; a disposable ed25519 key is generated per run for the SSH fixture. Containers are torn down (`down -v --remove-orphans`) in `finally`. Never push container state or credentials to any registry.

## Configuration

Host access: `docker compose -f tests/<fixture>/docker-compose.yml up -d --build` from the repo root (or just run the driver suite — it manages the lifecycle).

## Setup, seeding & first run

Docker Desktop running; nothing else.

## Testing

These ARE the integration tests; they run on release and after SSH/install changes.

## Operational notes & known limitations

- To disable for production-like runs: these fixtures never ship — `tests/` is gitignored/npmignored, so there is nothing to disable in the package.
- Slow Ubuntu archive mirrors can hit the 900s fixture-build timeout — re-run (layer cache resumes).
