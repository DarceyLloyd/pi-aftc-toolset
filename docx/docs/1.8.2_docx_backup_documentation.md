## Purpose

**Owns:** the pre-generation backup, count verification, `docs/` pruning, and the `.gitignore` additions.
**Does not own:** zipping (1.8.4's zip-old, run by the model at the end).
**Depends on:** nothing (pure fs/path). **Dependents:** 1.8.1.

## Public API & contracts

`runDocxBackup(projectRoot) -> DocxBackupResult { oldDir, moved[], copied[], partnerSkipped[], docsDirRemoved, docsLeftovers[], errors[], warnings[], firstRun }`. Throws only when `docx/old_docs/` cannot be created (the STOP rule).

## Internal architecture & data flow

Scope is a WHITELIST (never a blacklist) — framework/sub-project docs inside code folders are unreachable by construction:

| Source | Action | Dest under `docx/old_docs/` |
| --- | --- | --- |
| previous `docx/old_docs.zip` | move | `old_docs.zip` |
| previous `docx/` output | move | `docx/<name>` |
| root `*.md`/`*.markdown` (except AI files) | move | `<name>` |
| root `AGENTS.md`/`CLAUDE.md`/`GEMINI.md` | **copy** | `<name>` |
| `.github/copilot-instructions.md`, `.cursor/rules/*.mdc` | **copy** | same rel path |
| `docs/**/*.md` (minus exclusions/partners) | move | `docs/<rel>` |

Rules: partner docs (a `.md` sharing its basename with a non-`.md` sibling) stay; excluded dir names are never walked inside `docs/`; moved count must equal planned (mismatch → `errors`); `docs/` is pruned bottom-up and removed only when fully empty (else leftovers reported); `.gitignore` gains `docx/old_docs/` + `docx/old_docs.zip` once (idempotent, warning-only on failure). An `old_docs/` left by an aborted run is merged into, never deleted.

## Operational notes & known limitations

- The whitelist means a project keeping docs in a non-standard place (not root, not `docs/`) leaves them in place — generation then coexists with them.
