# 1.6 - SSH Subsystem

Credential-isolated SSH from inside pi: commands, interactive shells, transfers, and remote file management via a packaged Python Paramiko carrier.

## Purpose

**Owns:** everything SSH — saved connections, sessions, PTY shells, SFTP transfers, remote file ops, and the model tool surface.
**Does not own:** local shell execution (pi's bash), the footer/usage of SSH timing (1.4).
**Depends on:** 1.1, 1.2 (paths, config), 1.3 (dialogs). **Dependents:** none.

## Public API & contracts

Local commands: `/ssh-cm` (connection manager), `/ssh-connections`, `/ssh-connect [name]`, `/ssh-status`, `/ssh-select [id]`, `/ssh-shell`, `/ssh-close-shell`, `/ssh-interrupt`, `/ssh-upload`, `/ssh-download`, `/ssh-rename`, `/ssh-disconnect`, `/ssh-auto-accept-session-on/-off`, `/ssh-help`.

Model tools (opaque ids only): `ssh_status`, `ssh_connect(name)`, `ssh_disconnect`, `ssh_run`, `ssh_open_shell`, `ssh_send_keys`, `ssh_paste`, `ssh_resize`, `ssh_peek`, `ssh_interrupt`, `ssh_close`, `ssh_upload`, `ssh_download`, `ssh_list_dir`, `ssh_stat`, `ssh_read_file`, `ssh_write_file`, `ssh_mkdir`, `ssh_rename`, `ssh_remove`. Remote mutations require local-user confirmation.

## Internal architecture & data flow

```
model/local command -> ssh/index.ts -> session.ts -> carrier.ts --JSON-RPC/stdio--> python carrier (Paramiko) -> remote host
```

The carrier is lazily spawned on first use (`uv sync --locked` env), self-exits on stdin EOF and after an idle watchdog (`AFTC_SSH_IDLE_TIMEOUT_SEC`, default 10min), and stops 30s after the last session disconnects. Crash => `terminated` state, never silent restart. The security model is BINDING: the model never sees hosts/users/ports/passwords/keys — only saved names and opaque ids; credentials are held in memory for one auth attempt then cleared; all output is redacted (1.6.7) before reaching the model.

## Configuration

`ssh.json` in the data dir (names, host/user/port/timeout, optional key path, optional saved password) — managed only via `/ssh-cm`; never shipped, never exposed to the model. Auto-accept-host-keys toggle persists there too.

## Setup, seeding & first run

Requires Python 3.10+ and uv; `/aftc-install` runs `uv sync --locked` for the carrier and verifies the ready handshake.

## Testing

Extensive: `ssh-module-check`, `ssh-carrier-*-check` (lifecycle), `ssh-redaction-check`, `ssh-connection-form*`, `ssh-confirmation-overlay-check`, `ssh-replacement` (Docker end-to-end: commands, SFTP, forwarding, PTY), `pi-linux-ssh-verify`, idle/self-exit checks.

## Operational notes & known limitations

- Redaction matches saved metadata VERBATIM (case-sensitive substring) — deliberate over-redaction; make saved names unique-ish to avoid mangling common words (see 1.6.7).
- Port forwarding exists in the carrier (test coverage) but has no user/model surface — use `ssh -L/-R/-D` from your own terminal for tunnels.
