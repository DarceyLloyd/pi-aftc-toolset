## Function

Reliable large-script execution — the workaround for an upstream pi bug:
the built-in `bash` tool feeds inline commands through stdin and silently
TRUNCATES commands of a few KB+ (partial execution, no error). `run_script`
writes the script body to a temp file and runs `bash <file>`, so the only
inline command is tiny and nothing can be truncated. Source:
`run-script.ts` (337 lines). Bash-only by design (Windows: locate git-bash;
else system bash; no bash → clear error, never fall back to another shell).

## Model tool: run_script

Parameters (typebox): `script` (the full bash script body), `cwd?`,
`timeout?` (seconds; default 120, MAX 1800 — killed past it). Output:
combined stdout/stderr truncated like the bash tool (`truncateTail`,
DEFAULT_MAX_LINES/BYTES) + exit code. Temp script files are cleaned up.

## Commands

| Command | Behaviour |
| --- | --- |
| `/run-script-on` | `runScriptEnabled=true` → tool registered on next load |
| `/run-script-off` | `runScriptEnabled=false` → tool absent from the model's tool list |

Default: enabled (`runScriptEnabled=true`). Deliberately easy to remove
once pi fixes the bug: delete the module + its `createRunScript(pi)` line,
drop the preference — nothing else
references it.

## Runtime states

- Disabled: the tool is fully absent (not merely hidden).
- No bash found: execute() throws with a clear message.
- Timeout: script killed; output captured so far is returned.
