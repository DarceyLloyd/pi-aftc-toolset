## Function

Registers `/aftc-help`: the discovery screen for every command and
shortcut, and `/tools`: the scrollable list of every tool pi can call. Source: `help.ts` (260 lines). Built from the help registry
(1.2 `help-registry.ts`) so it can never drift from the real
registrations; skills + shortcuts are static rows (they are not
`pi.registerCommand` calls).

## Screen: /aftc-help viewer (surface)

Rendered via `showViewer` (1.3.2) — full-screen scrollable AFTC takeover;
long descriptions word-wrap inside the panel. Sections, in
`HELP_CATEGORY_ORDER`: General · Response · Interrupt · Navigation ·
Footer / cache / timing · Usage report · SSH · Replay · Keep it short ·
aftc-codex · Thinking · Audio notification · Providers — then static
**Skills** rows (`/skill:cache-audit`, `/skill:bulk-read`,
`/skill:aftc-codex`, language/framework/styling/backend/ops/media skills)
and **Shortcuts** rows (`alt+c`, `alt+n`, `alt+x`, plus pi built-in
`Ctrl+T` toggle-thinking noted).

## Screen: /tools viewer (surface)

`showViewer` list of EVERY tool pi can call, from `pi.getAllTools()`
(built-in + every extension + SDK), grouped: Built-in tools, then one
section per extension source file, then SDK tools; each row = tool name
(+ `(off)` when registered but not in `pi.getActiveTools()`) and its
description truncated to ~60 words (the viewer word-wraps). Headless
prints the same rows.

## Runtime states

- TUI: viewer overlay; Esc closes.
- Headless: `[aftc-toolset]`-prefixed print of the same content (never raw
  console.log in TUI — it interleaves with pi's redraws).

## Data

None persisted. Registry entries registered next to every command
(`registerHelpEntry`); aliases recorded in the primary entry.

## Rules / invariants

- One entry per PRIMARY command; every registered name must appear exactly
  once as command or alias; every entry must map to a real command —
  enforced both ways by the tests/ folder (see AGENTS.md).
- Shortcuts are NOT registry material — static `SHORTCUT_ROWS` here.
