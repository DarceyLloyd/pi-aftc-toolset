## Function

Injects a full-width themed horizontal rule immediately before each
assistant response — a clear visual break the moment the model starts
streaming. Source: `response.ts` (244 lines). No shared state with other
modules.

## Mechanism (three cooperating hooks)

1. `registerMessageRenderer("response-divider")` — the rule renders at
   paint time, exactly pane width (no wrap/truncation), colour from the
   active theme. Config: `HR_BG_COLOR=""` (solid-bar mode off),
   `HR_COLOR="border"`, `HR_CHAR="─"` (U+2500 light rule).
2. `before_agent_start` injects a custom divider message as the FIRST
   message of the turn: persisted to the session (survives /resume,
   /compact), rendered in the TUI, filtered from the LLM context by.
   Fires once per USER PROMPT — not per tool-call follow-up turn.
3. `context` strips divider messages from the model-visible list
   (defensively always, even when the feature is off).

## Command & states

`/aftc-response-divider` — toggles `responseDividerEnabled` (default ON):

- ON → OFF: renderer `render(width)` returns `[]` so existing dividers
  collapse on the forced repaint (`ctx.ui.setStatus` key also cleared);
  new prompts inject nothing.
- OFF → ON: status indicator `│ divider` (success colour) set; dividers
  return.
- Resumes correctly after `/resume` (old dividers persist in the session).
- Theme switch: rule recolours immediately (renderer re-invoked on
  invalidate).

## Rules / invariants

- The rule must NEVER appear in the LLM context (the `context` filter).
- Exactly one divider per user prompt, regardless of how many turns the
  task takes.
