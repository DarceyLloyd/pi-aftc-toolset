## Function

Single home for EVERY global keyboard shortcut the toolset registers
(AGENTS.md: never register a shortcut in another module; component-scoped
keys inside dialogs/overlays stay with their component). Source: `keys.ts`
(127 lines).

## Surface: the shortcuts

| Key | Action | Notes |
| --- | --- | --- |
| `alt+c` | Clear the input editor | `ctx.ui.setEditorText("")`; guard `ctx.hasUI` |
| `alt+n` | Insert a newline at the caret | `ctx.ui.pasteToEditor("\n")` (inserts at caret; `setEditorText` would move caret to end) |
| `alt+x` | Cut ALL input text to the clipboard | shared handler with `/aftc-cut-input` |

`/aftc-cut-input` (same handler): exists for discoverability via
`/aftc-help` and for RPC mode (no key event stream). In the TUI a slash
command consumes the editor line it was typed on, so the command usually
finds an empty editor there — use `alt+x` interactively.

Clipboard: pi's `copyToClipboard` (native addon → pbcopy/clip/wl-copy/
xclip/xsel/termux → OSC 52 fallback; throws when everything fails).
Injectable `KeysDeps.copy` for tests.

## Runtime states

- No UI (`!ctx.hasUI`): shortcuts no-op.
- Empty editor on cut: warn "Input is empty — nothing to cut."
- Clipboard failure: error line, editor text LEFT INTACT (cut clears the
  editor only AFTER a successful write — text is never lost).
- Success: emphasis "Cut N chars from the input to the clipboard."

## Rules / invariants

- Adding a shortcut: register here via `pi.registerShortcut`, guard with
  `ctx.hasUI`, add a static row to `SHORTCUT_ROWS` in help.ts (1.5.2),
  update `keys-readme.md`, extend the tests/ folder checks (see AGENTS.md). Check collisions
  against pi's `docs/keybindings.md`.
