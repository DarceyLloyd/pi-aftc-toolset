## Function

Hand work off between context windows with a handoff file (`./aftc-resume.md`
in the session cwd). Two commands: save the current work state, then (after
the USER runs `/new`) resume it in the fresh session. Source: `resume.ts`.
The `/new` is always the user's job — the toolset never starts a session on
its own.

## Commands

| Command | Args | Behaviour |
| --- | --- | --- |
| `/aftc-resume-save` | — | Stop current work and write `./aftc-resume.md`. An existing file is FIRST renamed to `aftc-resume-<last-modified>.md` (a timestamped snapshot — never overwritten). Waits for the model to settle (120 s cap), merges the extension-owned `## Resume metadata` block, verifies the file. |
| `/aftc-resume` | — | After `/new`: tells the model to read the handoff, load the codex resources it lists (only when codex is enabled), read its key files plus BOTH docx docs (`docx/project_documentation.md` and `docx/project_map.md` — each existence-checked, and every listed file must be read) and AGENTS.md, then continue. Fire-and-forget — the model takes over. |

## The handoff file

Model-written body (its work state), extension-owned `## Resume metadata`
block at the top:

- Model sections: `## Goal`, `## Current State`, `## Decisions Made`,
  `## Knowledge Learned`, `## Key Files`, `## Tasks & Progress`,
  `## Next Steps`, `## Open Questions` (+ `## Codex Resources` when codex
  is enabled).
- Extension metadata: project cwd, saved timestamp, codex enabled, codex
  resources, `status: pending` (the model flips it to `completed` when the
  work described in the file is done).

Single-writer rule: the model never writes the metadata block; the extension
merges it AFTER the agent settles (`ctx.waitForIdle()`), so the two never
race the file.

## Codex integration

A `tool_call` observe-hook tracks `codex_load` topics in session state
(cleared on every `session_start` — pi keeps modules alive across `/new`).
The save prompt embeds the tracked list when `aftcCodexEnabled` is true;
the resume prompt only mentions codex loads when it is true at resume time.
The flow NEVER depends on codex being on — the mandatory `## Key Files`
section is the fallback (resources auto-loaded by codex-detect never pass
through `codex_load`, so the model's own list covers those).

## Delivery

Idle → `sendUserMessage` (new turn now); busy → `deliverAs: "followUp"`
(queued until the current turn finishes). The save command then awaits
`ctx.waitForIdle()` (120 s cap) so it can verify what landed on disk; the
resume command is fire-and-forget.

## Failure modes

- Model never writes the file (aborted finalize): the extension writes a
  minimal metadata-only handoff and warns — the resume flow still has a
  file to find.
- Save timed out: warns and does NOT touch the file (the model may still be
  writing).
- Handoff under ~150 bytes: warns so the user checks before resuming.
- Resume with no handoff file: warns and lists any `aftc-resume-*.md`
  snapshots present.

## Runtime states

- Save success: emphasis `Work state saved to aftc-resume.md` (+ snapshot
  name when one was made), with a `/new` then `/aftc-resume` hint.
- Resume success: emphasis `Resume instruction sent…`.
- Headless: `[aftc-toolset]` stdout lines for every branch.
