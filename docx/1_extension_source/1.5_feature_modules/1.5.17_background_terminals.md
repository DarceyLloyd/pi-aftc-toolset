## Purpose

Let the model start long-running shell commands ("background terminals"),
keep working while they run, check on them, and stop them. The process
receives NO stdin (OS-level) — there is no way to send input later. stdout
and stderr are captured separately into bounded in-memory tails; the newest
output is always retained and head-drop is reported honestly.

## Surface

| Name | Kind | Purpose |
| --- | --- | --- |
| `bg_start` | model tool | spawn a command (command, title, working_dir) |
| `bg_status` | model tool | peek at one terminal's status + tail output |
| `bg_list` | model tool | list all tracked terminals |
| `bg_kill` | model tool | stop one or more (SIGTERM→SIGKILL tree) |
| `/bt` | command | scrollable list + stop one or all (TUI) / plain list (headless) |
| `/bt-on` / `/bt-off` | command | enable / disable (always registered) |

Widget: a one-line "N background terminals running — /bt to view or stop"
bar above the editor while ≥1 is running. Completion follow-up: a collapsed
transcript entry (custom message renderer) when a terminal exits.

## Architecture (plain TS, no Effect)

Three modules in `background-terminals/`, wired by one
`createBackgroundTerminals(pi)` line in index.ts (1.1):

- `background-terminal-manager.ts` — the process registry (pure
  `node:child_process`). Kill trees use `taskkill /pid X /T /F` on Windows
  (graceful taskkill orphans grandchildren holding the pipes) and
  process-group signals on POSIX; every teardown wait is bounded.
- `background-terminal-ui.ts` — the `/bt` screen: scrollable list of
  running terminals, `TERMINATE ALL` row at the top, Enter → yes/no
  confirm → kill → refreshed list (built on aftc-ui, 1.3.2); headless
  falls back to `aftcConsole.print`.
- `background-terminals.ts` — coordinator: tools, commands, widget,
  exactly-once completion follow-up (`pi.sendMessage` followUp + a deferred
  Map-keyed delivery), the result message renderer.

## Rules

- **Off by default** — `backgroundTerminalsEnabled` preference (config.json);
  `/bt-on` enables, `/reload` applies. When off, only `/bt-on`/`/bt-off`
  exist (the tools are absent from the model's tool list).
- **/bt is the stop surface** — a scrollable list of RUNNING terminals with
  a `TERMINATE ALL (n)` row at the top; Enter on a row asks a yes/no
  confirm, stops the selection, and returns to the refreshed list; Esc
  closes. Output inspection is `bg_status` (the old read-only viewer and
  the separate `/bt-kill` command were removed 2026-08). The TERMINATE ALL
  confirm states the factual safety: a kill signals only the terminal's own
  process tree/group (pi is its ancestor, never in the tree), so it can
  never stop this pi session or another shell — only programs started
  INSIDE a terminal stop with it.
- **Session-scoped** — `session_shutdown` disposes the manager, which
  SIGKILLs every tree (bounded); processes never survive `/new`/`/reload`.
- **No stdin, ever** — interactive commands will not work; `bg_kill` is the
  remedy for a stuck one.
- **Exactly-once completion** — a deferred, id-keyed delivery drained on
  `agent_settled` (or immediately when idle) makes double delivery
  structurally impossible; `bg_kill`/`bg_status` consume the settle they
  return.
- Max 8 running terminals (reservation is synchronous — start() spawns and
  registers before returning).
