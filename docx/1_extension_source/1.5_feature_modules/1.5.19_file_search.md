## Purpose

First-class, fast, gitignore-aware file discovery and content search for
the model: `fd` (find files/dirs by name) and `rg` (ripgrep content
search). Both shell out to the upstream Rust binaries — `fd` (sharkdp) and
`rg`/ripgrep (BurntSushi) — which are dramatically faster and more correct
than the `find`/`grep` one-liners models hand-write through the bash tool,
and which are the source of most search mistakes. The TypeScript is ONLY a
wrapper (binary resolution, arg building, validation, bounded output); the
search itself runs in the Rust binary.

## Surface

| Name | Kind | Purpose |
| --- | --- | --- |
| `fd` | model tool | find files/dirs by name, extension, glob, type, depth |
| `rg` | model tool | regex/literal content search across files |
| `/file-search-on` / `/file-search-off` | command | enable / disable (default on) |

## Binary resolution (lean)

On first use (or session start) the coordinator resolves each tool's binary
from PATH (`fd`/`fdfind` on Debian/Ubuntu, `rg`), probing with `--version`,
then falls back to pi's helper-binary dir `~/.pi/agent/bin` (pi injects it
into its own shell tool's PATH but the pi process often lacks it).
If neither exists, the tool reports a clear error with platform install
hints (winget/choco/scoop on Windows, brew on macOS, apt on Debian/Ubuntu).
No auto-download in v1 — the binaries are a normal package-manager install;
auto-download + SHA-256 verification is a future enhancement.

## Rules / invariants

- **On by default** (`fileSearchEnabled` preference, like `runScriptEnabled`).
- **Arg safety** — the pattern is always placed after a `--` separator so
  model input can never be parsed as a flag; paths have a leading `@`
  stripped and `~` expanded; `limit`/`max_depth`/`context` are clamped.
- **gitignore-aware by default** (fd/rg defaults); `hidden` opts into
  hidden files.
- **Bounded output** — 2000 lines / 50 KB via `truncateHead`, full output
  persisted to a temp file when truncated.
- **Clear errors + remediation** — a failed run returns the binary's stderr
  plus a hint (e.g. "literal text — set fixed_strings"); a missing binary
  says how to install it. These errors flow into the tool-error tracker
  (1.4.6).
- **No shell** — the binaries are spawned directly with an args array
  (`windowsHide`), never through a shell, so model input cannot inject
  shell syntax.
- 60 s timeout; honours the tool abort signal.

## Model guidance (prompt guidelines)

`fd` for finding by name, `rg` for searching content; use `rg`'s
`fixed_strings` for literal code snippets containing regex metacharacters;
keep using bash for multi-step pipelines that post-process listings.

## Tests

`tests/file-search-check/` — arg-building (pure, no binaries) and
classifier cases. The search itself needs `fd`/`rg` installed; the binary
is probed at runtime and errors clearly when absent.
