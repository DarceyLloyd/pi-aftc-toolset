## Function

Directory awareness: list the current directory (`dir.ts`, 195 lines),
show it as a card (`cwd.ts`, 120 lines), and quick-open frequent dirs in
the OS file manager (`quick-open-dir.ts`, 139 lines). Absorbed the retired
open-data-dir.ts; the retired `/cd` picker is gone (start pi in the target
directory instead).

## Commands & screens

| Command | Args | Behaviour |
| --- | --- | --- |
| `/dir` (alias `/ls`) | — | Runs the platform-native listing — `dir` on win32, `ls -la` on darwin/linux/other — via `execFileSync` (argument array, NO shell), and renders an inline card entry: title `📁 <~/path> (<Platform>)`, blank line, `Directory: …`, listing lines. `$HOME` shortened to `~`. |
| `/cwd` | — | Inline card with the current working directory only (same Box/customMessageBg style). |
| `/qd` | — | Quick dir access MENU (surface): title "AFTC Quick Dir Access", body "Choose your poison:", options "Open users data dir" (1.2 data dir, mkdir -p first) and "Open .pi data dir" (`~/<CONFIG_DIR_NAME>`). Choice launches explorer.exe / open / xdg-open detached+unref; emphasis "Opened: <dir>". Esc does nothing. |

## Data

`/dir`+`/cwd` use `pi.appendEntry` (types `dir-listing` / cwd type) —
persistent in the session, never in LLM context. `/qd` reads 1.2 paths.

## Runtime states

- Listing command failure: card title `📁 <dir> — error`, body `[error]
  Failed to run "<cmd>": …` — the card still renders.
- `/qd` target missing after ensure: warn "Directory not found: …".
- Headless `/qd`: menu falls back per aftc-ui rules.

## Extending `/qd`

Append one entry to `TARGETS` (`{value, label, resolve(), ensure?}`) —
nothing else to touch.
