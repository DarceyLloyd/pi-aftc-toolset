## Function

Save a prompt string once and re-execute it later as if freshly typed.
Source: `replay.ts` (224 lines). No closure state — config.json IS the
saved-prompt store.

## Commands

| Command | Args | Behaviour |
| --- | --- | --- |
| `/save-replay-prompt` | `<text>` (everything after the command; single line) | Stores the trimmed text in `replayPrompt` (config.json). Success message via custom message type `aftc-replay-saved` (rendered success-coloured, shown in session but FILTERED from the model context by the `context` hook). Empty text → console note, nothing saved. |
| `/replay` | — | Re-sends the saved prompt via `pi.sendUserMessage`. Idle → new turn immediately; busy → `{deliverAs:"followUp"}` queue (never interrupts). Emphasis shows an 80-char preview. |
| `/r` | — | Identical alias for `/replay`. |

## Data & migration

`replayPrompt` preference (default `""`). Legacy `replay.json` value is
migrated into config.json once at load, then the file is deleted.

## Runtime states

- No saved prompt + `/replay`: warning entry "No replay command found, set
  one via /save-replay-prompt <text>" (TUI) / stdout line (headless).
- Busy agent: queued as follow-up; confirmation says so.

## Rules / invariants

- Per AGENTS.md: never auto-store a saved replay prompt — default empty.
- The save confirmation must stay out of model context (`context` filter
  strips `aftc-replay-saved` custom messages).
