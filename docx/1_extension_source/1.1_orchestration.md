## Function

Owns the extension entry point and the module-layout contract. Source:
`extensions/aftc-toolset/index.ts` (180 lines) + `types.ts` (319 lines).
Does NOT own any feature behaviour — every feature self-registers inside its
own `create*` factory (1.2–1.8).

## Orchestration sequence (index.ts, exact order)

1. `migrateLegacyData()` — move legacy package-local data to the persistent
   data dir BEFORE any module reads it (1.2).
2. `aftcConsole.init(pi)` — register the emphasis entry renderer once (1.3.1).
3. Independent modules: `createAllowance`, `createUsageRecording`,
   `createUsageModule`, `createHelpModule`, `createInstallModule`,
   `createKeys`.
4. Text intro: `createTextIntro()` + `/aftc-intro-on|off` commands
   (registered in index.ts itself), `session_start` plays when enabled,
   `session_shutdown` stops. The intro FACTORY (`intros/intro-factory.ts`)
   is DISCONNECTED (2026-07) — files kept on disk (1.5.13).
5. `createTheme`, `createSshModule`, `createResponseDivider`, `createStfu`,
   `createDir`, `createCwd`, `createReplay`, `createKeepItShort`,
   `createThinkParser`, `createNotify`, `createQuickOpenDir`,
   `createDebugLog`, `createDocx`, `createAftcCodex`, `createRunScript`.
6. `createProviders(pi)` — DISABLED (commented): pi 0.81+ ships native
   provider support; module kept on disk (1.5.14).
7. Footer wiring: `createCore(pi, recorder, allowance)` →
   `createFooterWidget(pi, footerData)`. core owns data, widget renders;
   neither imports the other.

The whole body is wrapped in try/catch → `aftcConsole.logError`.

## Module-layout rules (the contract)

- One feature per file; entry is the orchestrator.
- Feature modules MUST NOT import each other; they may import shared
  utilities (1.2, 1.3) and pi packages.
- Cross-module wiring = dependency injection through index.ts using the
  structural interfaces in `types.ts` (structural typing — signatures match,
  no nominal imports).
- Adding a feature = new file + sibling `<name>-readme.md` + one
  `createXxx(pi)` line here + help-registry entries next to each
  `pi.registerCommand`.

## Runtime states

- Factory success: all modules log `loaded — …` via `aftcConsole.log`
  (stdout-gated by `debugLoggingEnabled`, always filed in debug.log).
- Factory exception: logged, pi continues without the toolset.
- `/reload`: modules stay loaded in pi; factories are NOT re-run — this is
  why all persistent files are read fresh per access (1.2).

## Rules / invariants

- Never start processes/sockets/timers in the factory — start from
  `session_start` or a command/tool (allowance's periodic timer is
  event-gated; footer's ticker starts with the widget component).
- Clean up in `session_shutdown`.
