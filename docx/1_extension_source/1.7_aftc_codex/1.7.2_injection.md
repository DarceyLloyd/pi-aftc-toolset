## Function

and decides what is relevant (`codex-detect.ts`, 371 lines).

## Injection (codex-inject.ts)

- `before_agent_start` injection. STABLE ALWAYS-ON content rides the
  CACHED system-prompt prefix (cache-friendly): `codex-rules.md` +
  `thought-and-action-guidance.md` (when `aftcCodexInjectGuidance`) + the
  generated `codex-resource-list.md`. Topic docs enter on demand via
  `codex_load` (1.7.4) + persisted READ ENTRIES (`CODEX_READ_ENTRY =
  "aftc-codex-read"`).
- The marker (`aftc-codex-marker`) is a NUMBERED checklist (D22): 1.
  codex_load the relevant/detected resources (and
  `documentation-and-planning` FIRST when the user starts planning or
  documentation work); 2. confirm loaded topics in one line; 3. locate
  the default entry point (AGENTS.md or whichever auto-inject file is in
  use) when not already in context; 4. LAST STEP - the docx handoff: an
  AFTC-DOCX block in the entry point means read
  `docx/project_documentation.md` + `docx/project_map.md` immediately
  after the codex loading.
- codex-intent.ts (D14) adds the optional heuristic layer: a planning/
  documentation-shaped user message (input event) earns a one-line
  suggestion to load `documentation-and-planning` - once per session,
  never when already loaded.
- Session lifecycle: prep notice banner ("AFTC CODEX") appended once per
  session (`noticedThisSession`); `state.persistState()`; disable strips
  everything from context.
- Rules-only mode (`/codex-inject-rules`): inject ONLY the Critical Global
  Rules section for THIS session; init/refresh/learn refuse while active;
  cleared by a fresh session (/new). Works with the feature disabled.
  Session state only — no config key (the retired `aftcCodexInjectMode`
  key is stripped by config.ts).
- Detection marker + auto-load notice appended when `aftcCodexAutoLoad`
  is on.

## Detection (codex-detect.ts)

- Returns `CodexDetectResult {topics: string[] (loadable), missing:
  string[] (mapped but no resource file yet — bootstrap hints)}`.
- Wide project scanning: package.json (every one in the tree, incl.
  word-boundary scan of scripts keys/values), lockfiles (incl. bun.lock),
  file extensions and framework markers for TS/JS, Python, Go, Rust,
  Java, C++, C#/.NET (+Blazor/MAUI), Twig, bash, batch, WiX, JUCE
  (CMakeLists content), CMake, Deno, nginx, Apache, MySQL (compose
  images), Electron, Shoelace, Node.js, scss→scss (not css), etc.
- Design domains imply `ui-ux-common`; mysql implies `database-common`.
  Legacy pre-v1 topic names (planning, documentation-generation,
  path-classification, design-common) are remapped to their v1 homes so
  stale pins never produce permanent "no resource yet" hints.
- Projects can PIN their stack with an
  `<!-- AFTC-CODEX-STACK topics: … -->` block in AGENTS.md / CLAUDE.md /
  .github/copilot-instructions.md / GEMINI.md / .cursorrules /
  .windsurfrules — the only detection path for design domains and target
  OS, and the manual override. Strict whole-word keyword scan of those
  files with an ambiguity stoplist.

## Runtime states

- Feature disabled & not rules-only → nothing injected.
- Compat unsafe → injection of stable content continues; load/init flows
  serve the guard message (1.7.1).
