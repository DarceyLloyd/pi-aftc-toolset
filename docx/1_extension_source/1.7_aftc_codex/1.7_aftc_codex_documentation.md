## Purpose

An OPT-IN, self-educating knowledge base: injects the maintainer's unified
codex rules + thinking guidance + a generated resource list into the
model's system prompt, and gives the model a `codex_load` tool to fetch
topic docs on demand plus write tools to record durable lessons. OFF by
default; fail-soft everywhere; never destroys user data; seeding is
copy-only. Owns everything under `extensions/aftc-toolset/aftc-codex/`
(10 TS modules + `scripts/`); consumes the shipped seed (2.1) and persists
the live copy in `<dataDir>/aftc-codex/` (1.2).

## Data layout (live vs seed)

- SHIPPED SEED (source only, replaced on pi update):
  `<packageRoot>/extensions/aftc-toolset/data/aftc-codex/` —
  `codex-rules.md`, `thought-and-action-guidance.md`,
  `markdown-guidance.md`, `codex-resource-removal-list.json` (cumulative
  list of obsolete resource paths, read from seed during sync — never
  copied live), `resources/` (category folders: languages, libraries,
  frameworks, engines, runtimes, tools, servers-and-containers, database,
  os, file-formats, ui-ux — ui-ux nests by platform: web/, desktop/, mobile/,
  plugin/; file-formats nests by format family: audio/ —
  plus the root-level `documentation-and-planning.md` and the generated
  `codex-resource-list.md`).
- USER LIVE COPY (per-user): `<dataDir>/aftc-codex/` (default; seed→live
  one-way copy; learned entries live here). Legacy pre-v1 layouts are
  migrated at startup by codex-migrate.ts (learned entries preserved,
  structural version `aftcCodexResourceVersion`).
- Seed version: `data/extension-config.json` → `codexVersion` (currently
  **25**). Live version: `aftcCodexVersion` preference (0 = pre-versioning,
  always out of date). Structural layout version: `aftcCodexResourceVersion`
  (0 = legacy, 1 = the v1 tree below).

## Lifecycle (normative)

1. Enable (`aftcCodexEnabled`) → first enable seeds the live copy with a
   choice: Pre-trained (rules + all shipped topic docs) or Fresh Start (rules +
   guidance only) (`aftcCodexSeeded` latch).
2. Structural migration (D18): once per extension load on the FIRST
   session_start, a legacy (pre-v1) live layout is moved/merged into the v1
   layout by codex-migrate.ts (learned entries preserved, idempotent,
   resumable), stamped via `aftcCodexResourceVersion`. Covers every legacy
   path any PUBLISHED release shipped (design/* + tools/{apache,docker,mysql,
   nginx,vsftpd}); user-CREATED files left in the legacy design/ folder are
   RELOCATED into ui-ux/ as live-only topics (never deleted — the live-only
   file evaluation sweep). Runs BEFORE any
   sync/removal; an incomplete migration skips that run's auto-sync. The
   maintenance body is fire-and-forget async: it captures `sctx.hasUI`
   BEFORE the first await and never touches the session ctx afterwards (pi
   replaces the session in -p mode; a stale ctx access throws and would
   crash the process), and the whole body is try/catch wrapped.
3. Auto-sync (`aftcCodexAutoSync`, ON): seeded + out of date →
   `runSeedToLiveUpdate` in the background: the seed removal list is
   applied first (obsolete topics deleted from live, empty category
   folders pruned), then the non-destructive merge runs (learned
   entries kept).
4. Compat guard: seed newer than live → `/codex-sync` (merge) or
   `/codex-install` (wipe + re-seed) before `codex_load` serves docs; the
   guard message is a normal tool result so the model can relay it.
5. `/codex-init` preps the session (inject + detect + fetch relevant
   docs); `/codex-refresh` strips and re-inits; `/codex-disable` strips
   from context; `/codex-inject-rules` = session-only rules-only mode
   (works even when disabled; cleared by /new).
