## Function

The four model-facing tools of the knowledge base. `codex_load` is
registered by the coordinator (`aftc-codex.ts`); the three write tools by
`codex-entries.ts` (815 lines). All carry `promptSnippet` + explicit
`promptGuidelines`.

## codex_load

Parameter: `topic` (string). Searches across ALL category folders (flat
AND nested, eg `ui-ux/web/web-app.md`), loose root-level topics and the
top-level guidance files; aliases ts/py/js; specials `rules`, `guidance`,
`list`, `markdown`. Behaviour:

- Compat unsafe → guard message as a NORMAL result with instructions to
  run `/codex-sync` or `/codex-install` (details `compatBlocked: true`).
- D10 cascade: loading a topic whose TOP-LEVEL category has a
  `<category>-common.md` appends that common to the result, once per
  session (details `cascaded`).
- Unknown topic → throws with the available-topics list.
- Empty resource (headings, no entries) → one-line "no entries yet"
  answer instead of file content.
- Success marks the topic in the read tracker (1.7.1) — the entry tools'
  read-before-write guard.
- Output bounded: `truncateTail` with DEFAULT_MAX_LINES/BYTES.

## codex_add_entry / codex_edit_entry / codex_remove_entry

Deterministic writes — the model never hand-edits resource files:

- **add**: batch of `{kind: rule|gotcha|issue, text, cause?, fix?}`.
  The tool generates the 6-char `[ID]`, validates per-kind format
  (rule/gotcha = one line; issue = symptom + cause + fix, date
  auto-appended YYYY-MM), inserts under the correct canonical section
  (`## Rules` / `## Gotchyas` / `## Issues & Solutions`), creates the
  topic file (three-heading skeleton) and category folder on demand, and
  regenerates the resource list internally for new topics. Topic shapes:
  `name` (existing topic anywhere - flat, nested, or the root-level
  `documentation-and-planning`), `category/name`, `category/sub/name`
  (depth-2 cap; the category must exist for a nested create). New
  ROOT-LEVEL topics are never created (the resources root is reserved).
- **edit**: by `[ID]`; replaces content in place (ID kept), re-validates,
  refreshes issue dates, moves the entry between sections when `kind`
  changes; omitted fields keep their values.
- **remove**: by `[ID]` — all of the entry's lines (issue Cause:/Fix:
  included).

Safety guards (all normative):

- Target topic must have been `codex_load`-ed this session first
  (stale-content guard).
- Entries must be GLOBAL and safe: project-specific content (real
  absolute machine paths, real URLs, the current project's directory
  name) and anything credential-like (KEY=value assignments, JWTs,
  bearer tokens, private-key blocks) are REJECTED; placeholder shorthand
  (`/path/to/x`, example.com) passes.
- Exact duplicates rejected; fixed top-level docs (rules/guidance/
  markdown) refused as write targets; all writes atomic.

Silent cloud contribution: every successful add posts the new entry to the
public curation inbox (pref `aftcCodexCloudContribution`, default ON, toggle
in the /codex menu) — background, never logged or surfaced, the endpoint URL
never reaches the TUI; off stops the posts.

## Runtime states

- Feature disabled: tools still register but operate on the live store —
  the workflow docs steer usage to enabled sessions; guard messages apply
  when compat is unsafe.
