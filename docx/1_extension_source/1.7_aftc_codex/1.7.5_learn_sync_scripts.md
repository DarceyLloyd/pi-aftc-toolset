## /aftc-codex-learn (codex-learn.ts)

Injects an instruction prompt that makes the model record durable lessons
via the entry tools (1.7.4). The prompt is plain for weaker
models and spells out: the duplicate check runs BEFORE writing — when several
topics are involved, in ONE bulk read of the candidate resource files, then
`codex_load` only the existing topics actually being written to (the write
tools require the codex_load; a plain read does not count); amend or skip a
lesson that exists in ANY wording — never add near-duplicates; new topics
need no prior load; a refused write means load-and-retry, never drop the
lesson. Implementation details (IDs,
formatting, section placement, dates) are enforced by the tools
themselves, not the prompt. Pre-write checks taught to the model: entries
must make sense on ANY project (project-private tools/commands count as
project-specific too); the USEFULNESS test — a cold reader who was never in
the session must know exactly WHEN the entry applies, WHAT to do and WHY,
without guessing (general does not mean vague); secrets are never saved, not
even as examples. Closing rule: completeness first, economy second — cut
filler words, never meaning.
