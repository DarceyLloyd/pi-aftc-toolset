(4 `.mjs` scripts).

## /aftc-codex-learn (codex-learn.ts)

Injects an instruction prompt that makes the model record durable lessons
via the entry tools (1.7.4). The prompt is plain for weaker
models and spells out: the duplicate check runs BEFORE writing — when several
topics are involved, in ONE bulk read of the candidate resource files, then
`codex_load` only the existing topics actually being written to (the write
tools require the codex_load; a plain read does not count); amend or skip a
lesson that exists in ANY wording — never add near-duplicates; new topics
need no prior load; a refused write means load-and-retry, never drop the
lesson. Implementation details (IDs,
formatting, section placement, dates) are enforced by the tools
themselves, not the prompt. Pre-write checks taught to the model: entries
must make sense on ANY project (project-private tools/commands count as
project-specific too); the USEFULNESS test — a cold reader who was never in
the session must know exactly WHEN the entry applies, WHAT to do and WHY,
without guessing (general does not mean vague); secrets are never saved, not
even as examples. Closing rule: completeness first, economy second — cut
filler words, never meaning.

## scripts/ (spawned by the extension, also runnable standalone)

| Script | Role |
| --- | --- |
| `sync-codex-resources.mjs` | Regenerate `codex-resource-list.md` from the resource files (RECURSIVE walk: nested topics list as path-form lines under one `## <category>` header; loose root-level topics under `## resources`) |
| `ensure-entry-ids.mjs` | Add missing unique 6-char entry IDs to resource files (recursive incl. root-level topics) |
| `seed-to-live-sync.mjs` | The non-destructive seed→live merge engine behind `/codex-sync` + auto-sync (1.7.1). Same-ID entries the user has not touched are UPDATED to the shipped wording via the live sync manifest (`codex-live-manifest.json`, sha256 per entry keyed `<rel>#<id>`, rebuilt on every sync); user-edited (or pre-manifest divergent) entries keep the live version and are reported as conflicts. Already recursive (path-keyed), so the v1 nested layout needs no engine change |
| `live-to-seed-sync.mjs` | MAINTAINER release sync (below; already recursive). Same-ID differences auto-resolve (live text wins); same-ID SECTION moves (a kind change in live) port too - the seed entry is relocated under the live entry's section (reported as MOVED), and a section heading the seed file lacks is appended as a new section at the end (reported as NEW SECTION) |

## /codex-live-to-seed [--apply] (maintainer, dev-gated)

Ports live-only resource entries + new topics into the SHIPPED seed
before a release so learned entries ship. Entry-level merge by `[ID]`;
same-ID-different-text is AUTO-RESOLVED — the live text wins and replaces
the seed entry in place (reported as UPDATED), and after an apply that updated entries the command injects a
follow-up prompt asking the AI to review the merged entries and correct
anything wrong. Same-ID entries that MOVED SECTION in the live copy (a
kind change via codex_edit_entry) are relocated in the seed to the live
entry's section (reported as MOVED); a section heading the seed file lacks
is appended as a new section at the end of the file (reported as NEW
SECTION). The generated `codex-resource-list.md` is never copied to
the seed. Dry run first;
`--apply` writes without the confirm viewer. When an apply actually wrote
seed files the command BUMPS the shipped `codexVersion` itself (a no-op
sync leaves it alone), stamps the user's live version (no false
out-of-date on the maintainer machine) and exits after the confirm.
Gate: only runs in a checkout with the `.dev` marker folder.
AGENTS.md documents the same flow; releasing is covered in 2.4.

## Runtime states

- Learn with the feature disabled / rules-only: refused with guidance.
- Dry run (no `--apply`): report shown, nothing written.
- Same-ID differences: auto-resolved, live text wins; after apply the AI is
  prompted to review the merged entries.
- Apply that wrote seed files: shipped `codexVersion` bumped, live version
  stamped, exit after the confirm.
- No-op sync (nothing to port): version untouched, explanation shown.
- Outside a `.dev` checkout: the maintainer command refuses.
