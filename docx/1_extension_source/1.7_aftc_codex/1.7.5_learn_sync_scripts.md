(4 `.mjs` scripts).

## /aftc-codex-learn (codex-learn.ts)

Injects an instruction prompt that makes the model record durable lessons
via the entry tools (1.7.4). The prompt is short and plain for weaker
models and spells out: loading an existing topic IS the duplicate check
(amend or skip a lesson that exists in ANY wording — never add
near-duplicates); new topics need no prior load; a refused write means
load-and-retry, never drop the lesson. Implementation details (IDs,
formatting, section placement, dates) are enforced by the tools
themselves, not the prompt. Pre-write check taught to the model: entries
must make sense on ANY project; secrets are never saved, not even as
examples.

## scripts/ (spawned by the extension, also runnable standalone)

| Script | Role |
| --- | --- |
| `sync-codex-resources.mjs` | Regenerate `codex-resource-list.md` from the resource files |

| `live-to-seed-sync.mjs` | MAINTAINER release sync (below) |

## /codex-live-to-seed [--apply] (maintainer, dev-gated)

Ports live-only resource entries + new topics into the SHIPPED seed
before a release so learned entries ship. Entry-level merge by `[ID]`;
same-ID-different-text is AUTO-RESOLVED — the live text wins and replaces
the seed entry in place (reported as UPDATED), and the command injects a
follow-up prompt asking the AI to review the merged entries and correct
anything wrong. The generated `codex-resource-list.md` is never copied to
the seed. Dry run first;
`--apply` writes without the confirm viewer. When an apply actually wrote
seed files the command BUMPS the shipped `codexVersion` itself (a no-op
sync leaves it alone), stamps the user's live version (no false
out-of-date on the maintainer machine) and exits after the confirm.
Gate: only runs in a checkout with the `.dev` marker folder.
AGENTS.md documents the same flow; releasing is covered in 2.4.

## Runtime states

- Learn with the feature disabled / rules-only: refused with guidance.
- Dry run (no `--apply`): report shown, nothing written.
- Same-ID differences: auto-resolved, live text wins; after apply the AI is
  prompted to review the merged entries.
- Apply that wrote seed files: shipped `codexVersion` bumped, live version
  stamped, exit after the confirm.
- No-op sync (nothing to port): version untouched, explanation shown.
- Outside a `.dev` checkout: the maintainer command refuses.
