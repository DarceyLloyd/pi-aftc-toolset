## Store (codex-store.ts)

- Live root: `<dataDir>/aftc-codex` (one-way seed → live); resources dir
  `<root>/resources`; seed dir
  `<packageRoot>/extensions/aftc-toolset/data/aftc-codex`.
- `readResource(topic)` searches ACROSS ALL category folders (flat AND
  nested one level deep, eg `ui-ux/web/web-app.md`) + loose root-level
  topics (`documentation-and-planning.md`) + the top-level guidance files
  (folder doesn't matter); aliases (ts/py/js)
  and specials `rules` / `guidance` / `list` / `markdown`
  (`codex-resource-list`).
- `listTopics()`, `listTopicPaths()` (every loadable topic as a
  `category/name` path — recursive incl. nested + loose root-level topics,
  sorted; feeds `/codex-list` + the `/codex-load` picker), category listing
  (known order first, extras sorted), `readResourceList()` ("" when missing).
- Spawns (never throws): `sync-codex-resources.mjs` (regenerate
  codex-resource-list.md) and `ensure-entry-ids.mjs` (add missing unique
  entry IDs).

## Seeding

Copy-only from seed; first enable asks Pre-trained vs Fresh Start
(1.7.3). `aftcCodexSeeded` latch prevents re-asking. Seeding never
overwrites an existing live copy. Seeding also stamps
`aftcCodexResourceVersion = 1` (the shipped seed is the v1 structural
layout; legacy live copies never pass through seed() - they are migrated
by codex-migrate.ts at startup, BEFORE any sync/removal application,
stamped only on full completion; covered by the tests/ folder - see AGENTS.md). The move map
covers every legacy path any PUBLISHED release shipped (design/* + the 5
moved tools/* files — verified against the release tarballs); after the
moves, a live-only evaluation sweep RELOCATES any remaining user-created
file in the legacy design/ folder into ui-ux/ as a live-only topic (never
deleted), so the published -> new upgrade is lossless (covered by the
tests/ folder — built from the published seed fixture; the 81-file
duplicate-union regression). See AGENTS.md.

## Version guard (codex-compat.ts)

- Shipped seed version: `data/extension-config.json` `codexVersion`
  (= 20 today). Live version: `aftcCodexVersion` preference (0 = unknown /
  pre-versioning → always out of date).
- `checkCodexCompatibility()` → `CodexCompatResult {isSafe, message}`;
  while unsafe, `codex_load` serves the guard message (normal result,
  model relays it) and init/refresh point at `/codex-sync` first,
  `/codex-install` second. The out-of-date banner re-checks real state on
  EVERY render (no phantom warnings after /reload), and auto-sync runs on
  the first session start of ANY kind (fresh, /reload, resume) once per
  extension load.
- Version bump helper for the maintainer flow (1.7.5).

## Sync core (codex-sync.ts)

`runSeedToLiveUpdate` — non-destructive merge backing BOTH `/codex-sync`
and startup auto-sync: the seed removal list is applied FIRST
(`applySeedRemovals`, codex-removals.ts — topics the maintainer
deleted/renamed in the seed are removed from live, empty category folders
pruned; unconditional, idempotent, fail-soft, confined to the live
`resources/` dir), then new topic docs copied, new entries appended to
their sections, fixed top-level docs updated, learned entries never
touched; conflicting edits → the user's version wins and is reported.
Removal lines (`REMOVED ...`) are prepended to the sync output. NOT
applied by `/codex-live-to-seed` (opposite direction) or `/codex-install`
(wipe + re-seed). The seed ships the cumulative
`codex-resource-removal-list.json` (forward-slash paths relative to
`resources/`); it is read from the seed dir on every sync and never
copied live.

## Read tracker (coordinator)

Durable read-entry dedup + the session-scoped set the entry tools'
read-before-write guard enforces (1.7.4).

## Runtime states

- Not seeded: commands steer to the seed choice (1.7.3); nothing to load.
- Seeded + up to date: normal operation; auto-sync no-ops.
- Seeded + out of date: guard messages steer to `/codex-sync` /
  `/codex-install`; `codex_load` serves the guard result, not stale docs;
  the banner re-checks live state on every render (no phantom warnings).
- Auto-sync running: background merge; learned entries kept; conflicts
  reported, user's version wins.
- Empty resource loaded: "no entries yet" one-liner instead of content.
