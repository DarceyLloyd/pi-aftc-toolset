## Function

Data-dir layout, fixed-doc seeding, resource access and the installed
version. Sources: `aftc-codex.ts` coordinator (registers `codex_load`,
owns the read-tracker + startup fixed-doc refresh), `codex-store.ts`.

## Store (codex-store.ts)

- Live root: `<dataDir>/aftc-codex`; resources dir `<root>/resources`; seed
  dir `<packageRoot>/extensions/aftc-toolset/data/aftc-codex`.
- `readResource(topic)` searches ACROSS ALL category folders (flat AND
  nested one level deep, eg `ui-ux/web/web-app.md`) + loose root-level
  topics + the top-level guidance files (folder doesn't matter); aliases
  (ts/py/js) and specials `rules` / `guidance` / `list` / `markdown`.
- `listTopics()`, `listTopicPaths()` (every loadable topic as a
  `category/name` path — recursive incl. nested + loose root-level topics,
  sorted; feeds `/codex-list` + the `/codex-load` picker), category listing
  (known order first, extras sorted).
- `runSyncScript()` spawns `sync-codex-resources.mjs` to regenerate
  `codex-resource-list.md` (never throws). Callers: `codex_add_entry`
  (new topic file), `/codex-learn`, Start Fresh.
- `readPackageVersion()` — the package.json version string ("" when
  unreadable).

## Seeding

`seed()` copies the 3 shipped fixed docs (rules / guidance /
markdown-guidance) into the live codex root (always the latest), creates
the empty `resources/` dir, and stamps `aftcCodexInstalledVersion` to the
package.json version. `ensureSeeded()` seeds only when not already seeded
(first enable). User resources and the SQLite DB are NEVER touched.

## Fixed-doc refresh (version)

On the FIRST `session_start` of any reason (once per extension load), if
`aftcCodexInstalledVersion` differs from `package.json`, the 3 fixed docs
are re-copied and the version stamped. This replaces the old codexVersion
guard + auto-sync: there is no seed→live merge, no removal list, no
structural migration, and no out-of-date pause. The SQLite usage DB is
left untouched (if it exists, it is never overwritten).

## Read tracker (coordinator)

Durable read-entry dedup + the session-scoped set the entry tools'
read-before-write guard enforces (1.7.4).

## Runtime states

- Not seeded: commands seed on first enable; nothing to load.
- Seeded: normal operation; the fixed-doc refresh no-ops unless the package
  version changed.
- Empty resource loaded: "no entries yet" one-liner instead of content.
