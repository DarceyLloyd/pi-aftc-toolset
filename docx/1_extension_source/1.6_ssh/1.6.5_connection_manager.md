## Function

Full-screen manager for saved SSH connections: list, add, edit, delete.
Owns NOTHING persistent — every mutation goes through the connection store
(1.6.3) via the add/edit/delete flows. Source:
`ssh/connection-manager/ConnectionManager.ts` (483 lines,
`ConnectionManagerScreen` + `openConnectionManager`). Opened by
`/ssh-connection-manager` (alias `/ssh-cm`). TUI-only — headless callers
are told to use the individual `/ssh-*` commands.

## Screen layout (AFTC takeover, panel width 78)

Title "AFTC SSH Connection manager". Populated state: `Saved connections
(N)` header, separator, scrolling list of `name` + `user@host[:port]` rows
(default port hidden); viewport capped to `terminalRows − 14` chrome lines,
max 20 rows; `Rows a–b of N` indicator only when overflowing. Empty state:
accent "No saved connections." + hint "Tab to Add new connection and press
Enter to create one." Bottom options row: `[ Add new connection ]` plus
`[ Edit ]` `[ Delete ]` when a row is selected. GRUB-style hints below the
panel. Only safe metadata is shown — no password, key path or fingerprint.

## Controls & keys

| Input | Effect |
| --- | --- |
| Tab / Shift+Tab | Cycle focus: list ↔ options row (empty list: option ↔ none) |
| ↑ / ↓ | List row ±1, wrapping (list focused) |
| PageUp / PageDown | Page by visible viewport, clamped |
| Home / End (Ctrl+A / Ctrl+E) | Jump to edges |
| ← / → | Move between options (options row focused) |
| Enter | Activate the focused OPTION (Enter on a list row is intentionally NOT handled) |
| Esc / Ctrl+C | Close the manager, restore pi |

Exactly one element looks active at a time (design.md): the focused list
row or the focused option carries the selection bar; when the options row
is focused the list is de-emphasised.

## Functionality (the flow)

`openConnectionManager` loops: show a freshly built screen (overlay
components are disposed on close — never reused) → resolve a
`ConnectionManagerResult` → run the follow-up → re-open:

- **add** → new-connection flow (1.6.6) → save.
- **edit** → shared edit screen (1.6.7) pre-filled; a saved password is
  PRESERVED (the edit screen never collects one); renaming removes the old
  record, with a replace-confirm on collision; cancel returns untouched.
- **delete** → "Are you sure? Yes/No" confirm (safe option highlighted) →
  remove the record. A live session started from the deleted record keeps
  running — the manager edits saved records, not active sessions.
- **cancelled** → exit.

## Runtime states

- Empty list: options row focused on open; Edit/Delete hidden.
- Deleted/vanished connection mid-flow: warn "That saved connection no
  longer exists."
- Rename collision: replace confirm; "no" returns to the list, original
  untouched.
