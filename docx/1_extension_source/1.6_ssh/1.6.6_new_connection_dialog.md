## Function

The Add-new-connection form used by the connection manager (1.6.5). A thin
wrapper over the AFTC form suite (1.3.2 `showForm`/`AftcForm`): GRUB-style
takeover, Tab/Shift+Tab focus, Enter advances/submits on
`[ SAVE CONNECTION ]`, Esc cancels. Source:
`ssh/connection-manager/NewConnectionDialog.ts` (148 lines). TUI-only (the
manager already guards).

## Fields (AftcForm-enforced)

| id | Label | Type | Validation / default |
| --- | --- | --- | --- |
| name | Connection name (required) | string | required non-empty (trimmed) |
| username | Username (required) | string | required |
| host | Host (required) | string | required |
| port | Port (leave empty for 22) | int | 1–65535, default 22 |
| timeout | Connection timeout seconds (leave empty for 30) | int | 1–300, default 30 (stored ms) |
| key | Private-key file path (optional) | string | optional |
| password | Password (optional — leave empty for key auth / passwordless) | password | optional, VERBATIM (untrimmed); never pre-filled |

## Functionality (`runNewConnectionFlow`)

Dialog → validations → then:

1. **Empty password?** → confirm "You didn't enter a password? Are you
   sure? Yes/No". No → back to the dialog with all entered values
   preserved (password field was empty by definition).
2. **Name collision?** (`findSshConnection`) → confirm "Replace saved SSH
   connection?" No → back to the dialog.
3. Save to the local store (1.6.3) → emphasis "SSH connection saved: <name>".

Returns the saved connection or null on cancel.

## Privacy

The password is collected here ONLY so it can be saved with the connection
(user-approved, local-only ssh.json). It is never logged, never shown
back, and covered by the redaction layer (1.6.4).

## Runtime states

- Cancel (Esc) at any step → null; nothing written.
- Re-show after a "No" confirm keeps values (except password).
