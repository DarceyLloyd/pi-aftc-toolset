## Function

Local storage for saved SSH connection metadata. Source:
`connection-store.ts` (170 lines). File: `<dataDir>/ssh.json` (1.2 paths).
Managed exclusively through `/ssh-cm` (1.6.5) — no other writer.

## Shape

```json
{
  "connections": [
    { "name": "…", "username": "…", "host": "…",
      "port": 22, "connectTimeoutMs": 30000,
      "identityFile": "…", "password": "…" }
  ],
  "ssh_session_auto_accept": false
}
```

`SshConnection`: name/username/host required; port 1–65535;
connectTimeoutMs > 0; identityFile + password optional. The optional saved
password is local-only: never exposed to model tools, never rendered,
always covered by redaction (1.6.4).

## API

`getSshConnections()`, `findSshConnection(name)`,
`saveSshConnection(connection)` (upsert by name),
`removeSshConnection(name)`, `getSshSessionAutoAccept()`,
`setSshSessionAutoAccept(value)`. All return defensive copies.

## Rules / invariants (binding)

- **NO in-memory cache** — same contract as config.json (1.2): every read
  hits disk fresh; every save is a fresh read-modify-write. Hand edits to
  ssh.json take effect immediately and are never clobbered.
- **No migration on read**: the file is exactly what the user / last save
  wrote; unknown fields survive (preserved through saves); a missing field
  is filled by the next save.
- **Atomic writes**: `<file>.tmp` + rename.
- **Fail-soft**: missing or corrupt file → empty store; a corrupt file is
  left untouched on disk for the user to fix, never silently clobbered.
- Validation (`isConnection`) filters malformed entries per-read without
  rewriting the file.

## Runtime states

- Empty store: pickers return null; `/ssh-connect` points at `/ssh-cm`.
- Corrupt JSON: treated as empty until the next successful save replaces it.
