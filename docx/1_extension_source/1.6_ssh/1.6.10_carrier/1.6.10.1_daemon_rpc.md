## Function

The process skeleton: entry point, stdin/stdout JSON-RPC loop, method
dispatch table and lifecycle. Sources: `__main__.py` (12 lines),
`daemon.py` (241), `rpc.py` (511). The carrier sub-project folder is
read-only for docs (1.6.10).

## Wire contract

- One JSON object per line; requests on stdin, responses + notifications
  on stdout, diagnostics on stderr (not protocol). Stdout writes are
  lock-protected against worker-thread interleaving.
- Startup handshake: `{"ready": true, "version": <ver>, "pid": <pid>,
  "capabilities": ["exec","sftp","shell","forward","env","monitor"]}`.
- `initialize` echoes protocol info; `ping` liveness; `shutdown` clean
  exit 0. SIGTERM/SIGINT and stdin EOF also exit cleanly (0).

## Dispatch

`rpc.py` keeps a `_METHODS` registry populated by `@_register("<name>")`
decorators — the full method list lives in the
[parent doc](./1.6.10_carrier_documentation.md). Parameter validation via
`_require_str`/typed helpers raises `INVALID_PARAMS` (-32602); unknown
methods → -32601; handler exceptions map to typed `RpcError` codes
(1.6.10.4) or -32603.

## Runtime states

- Ready (handshake sent) → serving → terminated (shutdown/EOF/signal).
- Malformed line → -32700 parse error response, loop continues.
- `session_lost` notifications arrive from the monitor thread (1.6.10.2)
  and are written through the same locked stdout path.
