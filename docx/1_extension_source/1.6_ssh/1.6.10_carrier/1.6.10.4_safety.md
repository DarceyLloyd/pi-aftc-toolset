## Function

The safety primitives of the carrier: key encoding, redaction and the
error-code catalogue. Sources: `keys.py` (154), `redaction.py` (53),
`errors.py` (49).

## keys.py — symbolic key encoder

Translates symbolic key names → terminal byte sequences for `send_keys`
(shell mode, 1.6.10.2): Ctrl+A…Ctrl+Z control bytes, arrows, Home/End,
PageUp/PageDown, Insert/Delete, F1–F12+, Enter/Tab/Escape/Backspace —
case-insensitive with common aliases. Unknown names are rejected with
`INVALID_PARAMS`.

## redaction.py

Carrier-side scrubbing so diagnostics written to stderr never leak
connection secrets (passwords, passphrases, key material) — mirrors the
TS boundary layer (1.6.4) on the Python side.

## errors.py — RpcError + codes

`RpcError(code, message, data?)`. Full code table in the
[parent doc](./1.6.10_carrier_documentation.md); highlights:

- -32041 `HOST_KEY_UNKNOWN` — approvable by the host for the pi session.
- -32042 `HOST_KEY_CHANGED` — ALWAYS rejected; never approvable.
- -32010 command timeout / -32060 transfer cancelled — the two codes the
  TS layer maps to named safe messages (1.6.4).

## Rules / invariants

- Error payloads carry NO endpoint or credential data — numeric code +
  generic message only.
- Key bytes are derived, never echoed back, in responses.

## Runtime states

- Known key name → byte sequence sent to the PTY.
- Unknown symbolic key → INVALID_PARAMS (-32602); nothing is sent.
- Redaction miss is impossible by construction: every diagnostic line is
  scrubbed before it reaches stderr.
