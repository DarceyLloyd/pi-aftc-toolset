## Purpose

`aftc-ssh-sidecar` — the packaged, uv-locked Python process that provides
multiple SSH sessions to the extension over line-delimited JSON-RPC on
local stdin/stdout. Paramiko-backed. Opens NO local HTTP service or
listening socket. The TypeScript host (1.6.2) starts it with
`uv run --locked --project <carrier-dir> python -m aftc_ssh_carrier`
(`uv.exe` on Windows), argument arrays, no shell.

This is a SUB-PROJECT: own manifest (`pyproject.toml`, hatchling build,
`aftc-ssh-sidecar` console script), own language/runtime and lockfile
(`uv.lock`). Its folder is READ-ONLY for documentation; it is documented
entirely from docx.

- Entry: `aftc_ssh_carrier.__main__:main` (== `python -m aftc_ssh_carrier`).

## Protocol (summary)

- One JSON object per line. Stdin = requests/notifications; stdout =
  responses + notifications (`{"notify": …}`, no id); stderr =
  human-readable diagnostics (NOT protocol).
- Startup: `{"ready": true, "version": …, "pid": …, "capabilities":
  ["exec","sftp","shell","forward","env","monitor"]}` then the read loop.
  Protocol version 1 expected by the TS client.
- Shutdown: `shutdown` method, SIGTERM/SIGINT, or stdin EOF — all clean
  exit 0 (child self-exits when the host pipe closes — AGENTS.md
  subprocess contract). Idle backstop: `AFTC_SSH_IDLE_TIMEOUT_SEC`
  (default 600 s) self-exit when stdin is quiet and no work is active;
  the TS host's 30 s reaper normally wins first.
- 35 registered methods: `initialize, ping, shutdown, connect, disconnect,
  list_sessions, get_session, run, expect, upload, download, cancel_transfer,
  read_file, write_file, list_dir, mkdir, rename, remove, stat, chmod, chown,
  open_shell, close_shell, list_shells, send_keys, paste, peek, resize_shell,
  interrupt_shell, forward_local, forward_remote, forward_dynamic,
  list_forwards, cancel_forward, get_env, set_env`.
- Notifications: `session_lost` (monitor), `transfer_progress`
  (transferId, bytes, total).

## Error codes (errors.py — all)

JSON-RPC standard: -32700 parse, -32600 invalid request, -32601 method not
found, -32602 invalid params, -32603 internal. Custom: -32002 connection
failed, -32003 auth failed, -32004 unknown session, -32005 unknown shell,
-32006 unknown forward, -32010 command timeout, -32011 channel closed,
-32020 file not found, -32021 permission denied, -32022 path is directory,
-32030 port in use, -32040 key load failed, -32041 host key unknown,
-32042 host key CHANGED (always rejected), -32050 no carrier, -32060
transfer cancelled. The TS side maps -32010/-32060 to safe model messages
(1.6.4).

## Bounds & guarantees

- `run` stdout/stderr capped 256 KiB each (`truncated: true`); `stdinText`
  UTF-8 ≤ 64 KiB (never a credential channel).
- SFTP: regular files or directory trees; symlinks never followed or
  recreated; empty dirs + binary files supported; per-session SFTP lock for
  the whole operation (paramiko's sync reader is not thread-safe);
  chunked transfers so `cancel_transfer` (opaque id, never takes the lock)
  can abort; temp file removed on cancel/failure; atomic destination
  replace where supported; opt-in `preserve` (mtime/atime + permission
  bits).
- Host-key policy: unknown keys → -32041 (host may approve per pi
  session); changed keys → -32042 always.
- All stdout writes lock-protected (worker threads can't interleave).

## Setup / installation

Handled by `/aftc-install` (1.5.3): `uv sync --locked` in this dir +
verification probe `uv run --no-sync --project <dir> python -c "import
paramiko, aftc_ssh_carrier"`. Recovery guidance is platform-specific when
Node/Python/uv is missing.
