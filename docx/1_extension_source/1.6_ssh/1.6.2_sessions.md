## Function

`SshSessionManager` — the single source of truth for active SSH sessions:
keeps carrier identifiers and credentials INSIDE the local extension, hands
out opaque ids, and drives the carrier client (`carrier.ts`). Source:
`session.ts` (431 lines) + the JSON-RPC client half of `carrier.ts` (410
lines). No UI; consumed by 1.6.1.

## Public surface

- `SshSessionView {id, name, connectedAt}` — opaque id, safe to show.
- `SshStatus {connected, carrierState: "idle"|"ready"|"terminated", sessions[]}`;
  `formatSshStatus()` renders both the `/ssh-status` line and `ssh_status`
  tool text.
- Manager methods: `connect(request, approved?)` (throws
  `SshHostKeyApprovalRequired` when a new key needs approval), `disconnect`,
  `list`, `select`, `selected`, `getStatus`, `run`, `openShell`,
  `sendKeys`, `paste`, `resizeShell`, `closeShell`, `interrupt`, `peek`,
  `upload`, `download`, `stat`, `listDir`, `readFile`, `writeFile`,
  `mkdir`, `rename`, `remove`, `redactText(sessionId, text)`.
- Remote paths are normalised (`remotePath`: leading `@` stripped, NUL /
  backslash rejected, posix-normalised).

## Lifecycle

1. Lazy carrier start on first connect (never at extension load — AGENTS.md
   subprocess rules): spawn `uv run --locked --project <carrier-dir> python
   -m aftc_ssh_carrier`, argument array, no shell; ready handshake within
   `START_TIMEOUT_MS` 15 s; protocol version check.
2. Requests: line-delimited JSON-RPC, 60 s default timeout
   (`REQUEST_TIMEOUT_MS`), abort-signal aware; `SshCarrierRequestError`
   carries numeric codes only.
3. Multi-session: carrier session ids map 1:N to the manager's opaque ids;
   re-connecting a name returns the SAME opaque id.
4. Idle reaper: when no sessions remain, the carrier stops after
   `REAPER_GRACE_MS` 30 s; a reconnect cancels the reap. Carrier
   `session_lost` notifications prune dropped sessions.
5. Shutdown: `session_shutdown` terminates the carrier (stop grace 3 s).

## Runtime states

- Carrier `idle` (spawned, not ready), `ready`, `terminated`.
- Connect failure: safe error categories (1.6.4); changed host key →
  carrier rejects regardless of auto-accept.
- Output truncation: carrier caps stdout/stderr at 256 KiB each
  (`truncated: true`); manager/tool layer re-bounds to 50 KB for the model
  (1.6.1).
