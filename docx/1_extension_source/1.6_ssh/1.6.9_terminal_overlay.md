## Function

The full-screen interactive SSH terminal. Same AFTC takeover frame as
every toolset screen; the remote PTY renders inside the panel as a LIVE
virtual screen (1.3.3), so cursor-addressed programs (nano, vim, htop,
top, less) work properly and pi's text can never bleed through. Source:
`ssh/terminal-overlay.ts` (198 lines, `SshTerminalScreen`). Opened by
`/ssh-shell` (1.6.1) on the selected session.

## Screen layout

Panel width capped at 110 (full-bleed on narrower terminals); chrome is 8
lines — the terminal viewport gets everything else (min 20 cols × 4 rows).
The remote PTY is resized (`ssh_resize`) to match the inner viewport.
Hints below the box.

## Keys

| Input | Effect |
| --- | --- |
| Text / paste | Forwarded; multi-character paste sent as bracketed paste |
| Navigation, function keys (incl. f13–f16 encodings), editing keys | Forwarded as named keys |
| Ctrl chords (ctrl+a … ctrl+z) | Forwarded |
| Esc | Forwarded to the REMOTE program (use it to close remote dialogs) |
| Ctrl+] | LOCAL escape chord — closes the screen (never forwarded) |

`terminalKey()` maps pi key events to the carrier's key vocabulary.

## Data & polling

- Reads via bounded `ssh_peek` polling every `POLL_INTERVAL_MS` 150 ms;
  the timer stops when the shell closes, fails, or the screen is dismissed.
- Feeds the VT100 screen (1.3.3), renders span rows with the
  dark-background colour policy.
- Resize: viewport changes set `resizePending`; one resize RPC per change.

## Runtime states

- Shell closed remotely → screen dismisses back to pi.
- Poll failure → polling stops, screen exits cleanly.
- Truncated snapshot → truncation marker rendered.

## Rules / invariants

- Ctrl+] is the ONLY local exit; Esc belongs to the remote program (also
  stated by `/ssh-help`).
- No credential or host data appears in the frame (title shows the
  connection name only).
