## Function

Minimal VT100/xterm virtual screen for the AFTC UI toolkit. Interprets the
SSH carrier's raw PTY byte stream (1.6.9 feeds it) so cursor-addressed
programs — nano, vim, htop, top, less — render as a real terminal would
instead of garbled scrollback. Output is `AftcSpan` rows (the shared UI
vocabulary), NOT raw ANSI. Source: `ui/terminal-screen.ts` (593 lines).
Does not own the overlay it renders inside (1.6.9) or the PTY transport
(1.6.2/1.6.10).

## Public API

`new TerminalScreen(cols, rows)` → feed PTY output; read span rows for
composition with the panel primitives of 1.3.2. Colours resolve to
`#rrggbb`: SGR 30–37 / 90–97, the 256-colour cube and truecolour all map
to hex.

Colour policy argument on render: `"raw"` keeps the faithful hex mapping
(parser tests); `"dark"` adapts for the overlay's solid black background —
light backgrounds crushed to a dark shade of the same hue with near-white
text, low-contrast foregrounds lightened (hue preserved) past a luma floor.
The cursor cell always keeps its raw inversion.

## Supported controls

SGR (colour/bold/reverse) · CUP/CUU/CUD/CUF/CUB/CNL/CPL/CHA/VPA cursor
moves · ED/EL erases · IL/DL/ICH/DCH/ECH line/char insert-delete · SU/SD
scrolls · DECSTBM scroll regions · IND/NEL/RI · save/restore cursor · DEC
graphics charset (line drawing) · alternate screen (`?1049`/`?47`/`?1047`) ·
cursor visibility (`?25`). OSC sequences are skipped.

## Known limitations

- Wide cells (CJK/emoji) are NOT supported — every code point occupies one
  column.
- Underline/dim attributes are dropped (AftcSpan has no such channel).

## Runtime states

- Empty screen → all-space cell grid (palette defaults).
- Split escape sequences across feed chunks are handled (covered by tests).

## Testing
