## Function

Centralised facade for everything the toolset writes to the user's console.
Owns the accent-coloured "emphasis" entry renderer and the `[aftc-toolset]`
stdout diagnostics. Does not own dialogs (1.3.2) or any feature behaviour.
Source: `ui/aftc-console.ts` (167 lines).

## API (exact)

| Call | Transport | Use for |
| --- | --- | --- |
| `init(pi)` | registers the `aftc-console-emphasis` entry renderer | once per session, from index.ts only; idempotent on /reload |
| `emphasis(ctx, text)` | `pi.appendEntry` accent-coloured line | status / success / state change (NOT warnings) |
| `warn(ctx, text)` | `ctx.ui.notify("warning")` | action could not proceed (nothing selected, missing args) |
| `error(ctx, text)` | `ctx.ui.notify("error")` | hard failure |
| `info(ctx, text)` | `ctx.ui.notify("info")` | rare neutral aside |
| `log(text)` | `console.log("[aftc-toolset] …")`, gated | routine diagnostics ("loaded — …", churn notes) |
| `logError(text)` | console, NEVER gated | failure diagnostics |
| `print(text)` | console, never gated, not filed | headless command responses |

## Data

- `log`/`logError` lines are ALWAYS appended to `<dataDir>/debug.log`
  (1.2 paths): rotating 5 MB cap with one `debug.log.old` generation.
- The stdout echo of `log()` is gated by the `debugLoggingEnabled`
  preference (default OFF — clean TUI; `/aftc-debug-log-on|off`, 1.2).
  `logError` stdout is never gated — a flag can never silence a failure.

## Runtime states

- Before `init()` / host without entry-renderer API: `emphasis` falls back
  to a dim info line (fail-soft; tests and stripped hosts).
- No UI: warn/error/info degrade to stdout lines.

## Rules / invariants

- NEVER use raw `ctx.ui.notify` or bare `console.log("[aftc-toolset]…")`
  in feature code — always this facade (AGENTS.md).
- Severity contract: emphasis = accent/state, warn = blocked, error = failed.
