## Purpose

The shared TUI output layer every feature builds on. Three LEAF utilities
(they import only `@earendil-works/pi-tui` and each other type-only — never
feature modules), so the "features must not import each other" rule is not
violated by importing them:

- **1.3.1 aftc-console** — severity-tagged transcript + stdout diagnostics.
- **1.3.2 aftc-ui** — GRUB-style full-screen takeover overlays: menus,
  confirms, forms, inputs, scrollable viewer + the fixed AFTC palette and
  panel/span primitives.
- **1.3.3 terminal-screen** — VT100/xterm virtual screen that turns the SSH
  carrier's raw PTY stream into rendered spans.

Depended on by: every surface in the [sitemap](../1_tui_sitemap.md). Depends
on: `@earendil-works/pi-tui` only (+ config/paths for console's debug gate
and log file).

## Public API & contracts (summary)

- `aftcConsole.init(pi)` once per session; `emphasis/warn/error/info` for
  transcript lines, `log/logError` for `[aftc-toolset]` diagnostics,
  `print` for headless command responses.
- `showMenu`, `showConfirm`, `showForm`, `showInput`, `showIntInput`,
  `showFloatInput`, `showViewer` — all async, resolve `null`/`false` on
  cancel, full-screen takeover in TUI mode.
- `AftcUi` / `AftcMenu` / `AftcForm` / `AftcViewer` classes for composite
  screens (the SSH manager builds on `AftcUi` directly).
- `TerminalScreen(cols, rows)` — feed PTY bytes, read `AftcSpan` rows.

## Rendering safety rules (both files enforce them)

- Every returned line is EXACTLY `width` visible columns (over-wide lines
  crash pi's TUI).
- Spans are independently styled and SGR-terminated; never nested.
- `truncateToWidth` (pi-tui) is ANSI-aware — escape codes are safe.
