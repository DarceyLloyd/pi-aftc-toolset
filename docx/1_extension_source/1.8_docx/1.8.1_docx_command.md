## Function

The command handler and its gates. Source: `docx/docx.ts` (490 lines).
Project root = `ctx.cwd`. Args: `--yes` (skip confirmations; headless),
`--type <key>` / `--type=<key>` (headless type selection).

## Flow (exact order)

1. **Hard gate**: `ctx.getContextUsage().percent >= 25` → refuse. TUI:
   full-screen info MODAL "context window too full" explaining the
   compaction-corruption risk and the fix (/new, then /docx). Headless:
   warn line. Applies EVEN WITH `--yes`.
2. **Confirmations** (skipped by `--yes`; headless without `--yes` that
   needs confirmation is told to re-run with `--yes`):
   - Advisory at ≥20% usage: CONFIRM modal — usage is modest (measured
     5–8% of a 1M window, under 20% even for large projects) but the run
     is LONG; highly advises /new first ("Proceed anyway" / "Exit").
   - Backup confirmation MODAL: warns all previous documentation is moved
     into ./docx/old_docs/ (zipped at the end), advises making your own
     backup first; sets the time expectation.
3. **Project-type selection**: TUI picker MODAL (10 types, auto-detect
   pre-selected); headless: `--type`, else auto-detect, else refuse with
   the key list.
4. **Backup** (1.8.2) — any error aborts before the model is engaged.
5. **Prompt assembly & injection**: CORE execution prompt extracted from
   section 18 of the shipped guide (the fenced ```text block — the guide
   is the single source of truth, never duplicated), the chosen pack
   appended after `---`, `[PROJECT_PATH]` / `[GUIDE_PATH]` /
   `[MAP_SCAN_PATH]` / `[LINK_AUDIT_PATH]` / `[ZIP_OLD_PATH]` substituted
   with forward-slash absolute paths; prefixed with the "You are running
   /docx" banner, project-type line and BACKUP STATE summary (moved /
   copied / partner-skipped / docs-leftovers / first-run text). The whole
   guide is appended after the prompt. Injected as a user message — the
   model then does the generation (the model also runs map-scan /
   link-audit / zip-old mid/end-run).

## Auto-detect (`detectProjectType`)

Heuristic pre-select (the user confirms in the picker; headless without
`--type` it is the decider): probes root files (package.json, compose,
Dockerfiles, source extensions, …) in the DOCX_TYPES order. No match →
null (picker without pre-select; headless refuses).

## Runtime states

- First run (no previous docs): backup summary says so; steps referencing
  old docs are skipped by the model.
- `--yes` + ≥25% context: still refused (hard gate).
- Missing guide/pack file → prompt assembly returns null → error line.

## Rules / invariants

- Exactly ONE type pack per run — the old all-in-one prompt is gone.
- The model never moves/zips docs itself (backup is tooling-owned; the
  final zip is `scripts/zip-old.mjs`).
