## Function

Deterministic, whitelist-scoped backup of pre-existing documentation into
`./docx/old_docs/` (relative-from-root paths preserved). Source:
`docx/docx-backup.ts` (346 lines). Identical for `/docx` and
`/docx-update`; runs BEFORE the model is engaged; any error aborts the
whole command. `old_docs/` stays readable for the WHOLE run (the model's
recon input); the final zip is made at the END of the run by
`scripts/zip-old.mjs`. Result shape `DocxBackupResult`: `moved[]`,
`copied[]`, `partnerSkipped[]`, `docsLeftovers[]`, `docsDirRemoved`,
`firstRun`.

## What is moved

- Root-level project `.md` files (README.md, tasks.md, resume.md, …).
- Everything under `./docs/`.
- Any previous `./docx/` output EXCEPT `old_docs/` and `backups/` — a
  re-run folds the previous output into the new backup automatically.
  `docx/backups/` (the accumulated timestamped backup zips) is NEVER
  folded or touched.

## What is COPIED (left in place)

AI context files — `AGENTS.md` and the known tool variants
(`.github/copilot-instructions.md`, `CLAUDE.md`, `GEMINI.md`,
`.cursor/rules/*`, …): the generation run edits AGENTS.md in place, so it
must stay at the root; the copy in old_docs is the recon hint.

## Partner + exclusion rules

- PARTNER docs (a `.md` sharing its basename with a non-`.md` sibling —
  the per-module `*-readme.md` next to code) are left in place: they
  belong to the code, not to the doc set (`partnerSkipped`).
- `./docs/` is only removed when fully emptied; non-documentation
  leftovers keep the dir and are reported (`docsLeftovers`).
- Excluded/never-touch folders (`.git`, `.bak`, `.old`, node_modules, …)
  are never walked.
- Move counts are verified against the collected count before generation
  starts.

## Final zip (tooling-owned, end of run)

`scripts/zip-old.mjs <root> <label>` packs `docx/old_docs/` into a
TIMESTAMPED zip inside `./docx/backups/` and deletes the staging folder:

| Command | Label | Zip name |
| --- | --- | --- |
| `/docx` | `original` | `Original Documentation Backup YYMMDD HHMM.zip` |
| `/docx-update` | `update` | `Documentation Backup YYMMDD HHMM.zip` |

`docx/backups/` accumulates across runs — every run adds one zip, none
are ever folded into a new backup or overwritten.

## Runtime states

- First run (nothing found): `firstRun=true`, old_docs stays empty.
- Corrupt/locked source file: counted as an error → abort (nothing
  half-moved).
- Restore path: unzip the relevant zip from `docx/backups/` and copy
  files back to their recorded paths.

## Rules / invariants

- The model NEVER moves or zips docs itself — backup and final zip are
  tooling-owned (`zip-old.mjs`, 1.8.4).
- `docx/old_docs/` + `docx/backups/` are added to `.gitignore` by the
  backup tooling (idempotent append under a `# aftc docx backup
  artifacts` comment).
