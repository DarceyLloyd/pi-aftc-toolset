## Function

Deterministic, whitelist-scoped backup of pre-existing documentation into
`./docx/old_docs/` (relative-from-root paths preserved). Source:
`docx/docx-backup.ts` (349 lines). Runs BEFORE the model is engaged; any
error aborts the whole command. Result shape `DocxBackupResult`:
`moved[]`, `copied[]`, `partnerSkipped[]`, `docsLeftovers[]`,
`docsDirRemoved`, `firstRun`.

## What is moved

- Root-level project `.md` files (README.md, tasks.md, resume.md, …).
- Everything under `./docs/`.
- Any previous `./docx/` output (incl. a previous `old_docs.zip`) — a
  re-run folds the previous output into the new backup automatically.

## What is COPIED (left in place)

AI context files — `AGENTS.md` and the known tool variants
(`.github/copilot-instructions.md`, `CLAUDE.md`, `GEMINI.md`,
`.cursor/rules/*`, …): the generation run edits AGENTS.md in place, so it
must stay at the root; the copy in old_docs is the recon hint.

## Partner + exclusion rules

- PARTNER docs (a `.md` sharing its basename with a non-`.md` sibling —
  the per-module `*-readme.md` next to code) are left in place: they
  belong to the code, not to the doc set (`partnerSkipped`).
- `./docs/` is only removed when fully emptied; non-documentation
  leftovers keep the dir and are reported (`docsLeftovers`).
- Excluded/never-touch folders (`.git`, `.bak`, `.old`, node_modules, …)
  are never walked.
- Move counts are verified against the collected count before generation
  starts.

## Runtime states

- First run (nothing found): `firstRun=true`, old_docs stays empty.
- Corrupt/locked source file: counted as an error → abort (nothing
  half-moved).
- Restore path: unzip `docx/old_docs.zip` and copy files back to their
  recorded paths.

## Rules / invariants

- The model NEVER moves or zips docs itself — backup and final zip are
  tooling-owned (`zip-old.mjs`, 1.8.4).
- `docx/old_docs/` + `old_docs.zip` are added to `.gitignore` by the
  backup tooling.
