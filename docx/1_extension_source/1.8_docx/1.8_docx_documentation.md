## Purpose

Two commands, one shared pipeline:

- `/docx` — regenerates a project's FULL documentation set into `./docx/`
  (root README last, master + structure map + mirrored ID tree +
  cross-cutting docs) following the shipped `documentation_guide.md`.
- `/docx-update` — reconciles an EXISTING `./docx/` set with the source
  of truth instead of regenerating: mints docs for new source files,
  retires docs for removed files (IDs marked reserved), corrects drifted
  docs in place, keeps map/master/index/sitemap in sync, then adjusts the
  root README.md IN PLACE (fact-check + minimal targeted edits; layout,
  formatting and tone preserved — never rewritten).

Both back up pre-existing documentation to `./docx/old_docs/` (model recon
input during the run), zipped at the END of the run into a timestamped zip
inside `./docx/backups/`. The work is done BY THE MODEL — this feature
owns the deterministic tooling around it: context gates, confirmation,
type selection, backup, prompt assembly and helper scripts. This very
documentation set was produced by it.

Owns `extensions/aftc-toolset/docx/` (docx.ts 579, docx-backup.ts 346,
`documentation_guide.md`, `prompts/` 10 packs, `scripts/` 4 helpers).
Does NOT own the generated output (belongs to the target project).

## Command surface

`/docx [--yes] [--type <key>]` (regenerate) and
`/docx-update [--yes] [--type <key>]` (reconcile an existing doc set;
requires an existing `./docx/` — refuses and points to `/docx`
otherwise). Both are registered in the General help category. Full flow
in [1.8.1_docx_command.md](./1.8.1_docx_command.md). Backup mechanics in

## Project types (exactly ONE pack injected, never the old all-in-one)

`web-app`, `basic-website`, `webgpu-webgl`, `desktop-app`, `juce-vst`,
`mobile-app`, `python-app`, `cli-tool`, `shell-scripts`, `generic`.
TUI: picker modal with auto-detect pre-selected. Headless: `--type <key>`,
else auto-detect, else refuse with the key list.

## Safeguards

- Context-window gates (both commands): ≥25% used → flat refusal (even
  with `--yes` — compaction mid-run could corrupt the docs); ≥20% →
  advisory recommending `/new` first.
- `/docx-update` refuses when no `./docx/` exists (nothing to reconcile —
  run `/docx` first).
- Confirmation modal (skippable with `--yes`, mode-specific wording):
  `/docx` warns that all previous documentation is moved into
  `./docx/old_docs/` and advises making a backup first; `/docx-update`
  explains the reconcile (docs preserved in place, README adjusted but
  never rewritten) and the backup zip.
- Deterministic backup (both commands) with verified move counts; ANY
  backup error aborts BEFORE the model is engaged.
- Framework/sub-project documentation is structurally untouchable: the
  backup only ever reads the project root, root `.md` files, `./docs/`
  and a previous `./docx/`. AGENTS.md is COPIED, never moved — it is
  edited in place by the run.

(update refusal without docx/, reconcile prompt + `update` zip label —
docx_test_07). Fixture projects: `tests/docx/*` (3.5).
