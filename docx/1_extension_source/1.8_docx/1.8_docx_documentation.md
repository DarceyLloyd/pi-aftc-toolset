## Purpose

`/docx` — regenerates a project's FULL documentation set into `./docx/`
(root README last, master + structure map + mirrored ID tree +
cross-cutting docs) following the shipped `documentation_guide.md`, with
the previous documentation backed up to `./docx/old_docs/` (zipped to
`old_docs.zip` at the end). The generation is done BY THE MODEL — this
feature owns the deterministic tooling around it: context gates,
confirmation, type selection, backup, prompt assembly and helper scripts.
This very documentation set was produced by it.

Owns `extensions/aftc-toolset/docx/` (docx.ts 490, docx-backup.ts 349,
`documentation_guide.md`, `prompts/` 10 packs, `scripts/` 4 helpers).
Does NOT own the generated output (belongs to the target project).

## Project types (exactly ONE pack injected, never the old all-in-one)

`web-app`, `basic-website`, `webgpu-webgl`, `desktop-app`, `juce-vst`,
`mobile-app`, `python-app`, `cli-tool`, `shell-scripts`, `generic`.
TUI: picker modal with auto-detect pre-selected. Headless: `--type <key>`,
else auto-detect, else refuse with the key list.

## Safeguards

- Context-window gates: ≥25% used → flat refusal (even with `--yes` —
  compaction mid-generation could corrupt the docs); ≥20% → advisory
  recommending `/new` first.
- Confirmation modal (skippable with `--yes`) warns that all previous
  documentation is moved into `./docx/old_docs/` and advises making a
  backup first.
- Deterministic backup with verified move counts; ANY backup error aborts
  BEFORE the model is engaged.
- Framework/sub-project documentation is structurally untouchable: the
  backup only ever reads the project root, root `.md` files, `./docs/`
  and a previous `./docx/`. AGENTS.md is COPIED, never moved — it is
  edited in place by the run.
