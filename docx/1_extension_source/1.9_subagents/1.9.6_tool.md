`createSubAgents(pi, deps?)` — the `aftc-codex.ts` analogue, wired by
the orchestrator with `{ allowance }` (1.4's `AllowanceProvider`).
Returns `{ getStatusSnapshot }` for the footer line. No processes or
timers start in the factory; children start lazily from the tool;
`session_shutdown` kills every tree.

## The `subagent` tool

Schema EXACTLY `agent / task / context / acceptance / target` —
NO `mode` field (v1 foreground-only), NO model/tools/skills/timeout/
budget (capabilities live in the profile — invariant 8). `promptSnippet`
+ `promptGuidelines` naming the tool explicitly; description carries
the deduped sub-agent roster. `execute(_id, params, _signal, onUpdate, ctx)`:

1. Feature gate: disabled -> throw ("run /007").
2. Agent lookup (qualified ids allowed, `@` stripped,
   `fallbackOperative` pref, unknown -> `unknown sub-agent` error
   listing known names).
3. Workspace: `target` resolved below `ctx.cwd` — no elevation.
4. `supervisor.startRun` with `resolveModel`, `preSpawnGate`
   (allowance), `parentCodexEnabled` (from `aftcCodexEnabled`),
   bounded `onUpdate` progress.
5. Result: text report; `failed`/`cancelled` THROW (pi marks the call
   an error); otherwise content + details + nested `usage` — child
   usage rides on the tool result and contributes EXACTLY ONCE to pi's
   native totals (invariant 13).
6. `renderCall`/`renderResult`: compact themed rows.

## Model resolution (BEFORE spawn)

`resolveSubAgentModel(spec, ctx)`: `inherit` -> the parent's active
model; exact `provider/modelId` via `ctx.modelRegistry.find`; fuzzy
substring (shortest-id wins); fallback arrays first-resolvable-wins;
throw = clean pre-spawn failure.

## Allowance gate (spending guard, design 13)

`evaluateSubAgentAllowanceGate(view, warnPercent)` (pure, exported):
null view -> NO gate; fires when any window >= warn percent. The
closure adds the UX: TUI menu (Don't spawn / Spawn anyway / Spawn +
don't ask again this session); headless auto-proceeds with a logged
warning; `allowanceGateEnabled` off skips entirely.

## Footer line

`buildSubAgentFooterLine(snapshot, colors, maxConcurrent)` (pure; the
line itself never reads config) ->
`Sub Agents running: 2/4 | Session cost: $0.14 | Agent avg task time: 1m 30s | Agents running: worker 42%, explorer 18%`
— active vs `maxConcurrent`, session sub-agent spend, average wall
time of completed runs this session (`—` when none), comma list of
running agent names (`—` when none). A `! ` prefix appears when any
run is stalled, looping or over the context threshold. Themed exactly
like footer lines 1-4: the caller passes the footer c1/c2/c3 color
helpers (`FooterLineColors` from `footer-widget.ts`) and the builder
returns an already-themed line. The orchestrator wires it into
`createFooterWidget` as the `subAgentLine(colors)` callback; the line
is ALWAYS visible while the feature is enabled and hidden only when
the feature is disabled or the `footerLineEnabled` toggle is off (it
no longer auto-hides when idle) — the footer widget stays
subagent-agnostic. The snapshot carries `runningAgents` (name +
latest context-window % per running agent, shown as `worker 42%` in
the Agents-running segment) and
`avgElapsedMs` (computed by the supervisor; average over
`state === "completed"` runs).

## Tool states

Feature disabled → the tool reports how to enable; unknown agent name →
`unknown sub-agent` error; near the subscription limit the allowance
gate asks the user to confirm before spawn (1.4.3); the footer line
hides only when the feature is off (`null` from the builder).
