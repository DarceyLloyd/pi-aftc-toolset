The feature's OWN config file `<dataDir>/subagents-config.json` —
deliberately not the shared `config.json` (self-contained, droppable;
the `ssh.json` precedent). Keys UNPREFIXED — the file is the namespace.

Contract (same discipline as `config.ts`):
- **No in-memory cache** — every read hits disk (pi keeps extension
  modules alive across `/new`; a cache would serve stale values and a
  later write would clobber hand edits).
- `setSubAgentPref` = fresh read-modify-write, atomic tmp+rename.
- Existing values are sacred: the load-merge backfills only
  missing/wrong-type keys.
- Optional project override `<cwd>/.pi/subagents-config.json` (project
  wins on load; the override file is never written).
- `enabled` ships **false** (new-feature rule); everything inside the
  feature (footer line, watchdogs, allowance gate, transcript) is on by
  default.

Key set (design section 14): feature/transport, capacity
(`preset` light/standard/heavy + `maxConcurrent`/`maxQueued`/
`maxRunsPerSession`), budgets (`defaultMaxTurns`, `graceTurns`,
`defaultTimeoutSeconds`), safety (`allowanceGateEnabled`,
`allowanceWarnPercent`, `stallDetectionEnabled`, `stallTimeoutSeconds`,
`loopDetectionEnabled`, `loopThreshold`), orchestration keys (inert
until their phase), UX (`footerLineEnabled`, `outputTranscript`),
capability gates (`codexAccessEnabled`, `codexWriteEnabled`).

API: `getSubAgentPref/setSubAgentPref`, `getSubAgentsConfigJson()`,
`getProjectSubAgentsConfigJson(cwd?)`, `SUB_AGENT_PRESETS`,
`setSubAgentPreset(preset)`.

## Config states

Missing `subagents-config.json` → built-in defaults; missing/wrong-type
keys are backfilled on read (fresh read-modify-write, never cached);
user values are never overwritten.
