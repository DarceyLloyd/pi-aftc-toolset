The coordinator: scheduling, child processes, run state, watchdogs,
cancellation, termination ladder. Foreground-only in v1 —
`startRun()` resolves with the `SubAgentRunResult` the tool returns.

## Flow

queued -> starting -> running -> ONE terminal state
(completed / blocked / failed / cancelled / timed_out).

1. Slots reserved BEFORE spawn (invariant 7): `maxConcurrent`,
   `maxQueued`, `maxRunsPerSession`.
2. `resolveModel` hook runs in the parent BEFORE spawn — unresolvable
   model = clean pre-spawn `failed` (never fails after spawn).
3. Run dir `<dataDir>/subagents/runs/<run-id>/`: meta.json,
   run-config.json (0600, the child's config), transcript.jsonl
   (events appended when `outputTranscript` allows), report.json.
4. Spawn (detached) -> readiness `get_state` request -> briefing
   `prompt` (task/context/acceptance/target — the ONLY data channel,
   all sizes bounded).
5. Events attributed per child handle (invariant 14): usage from
   assistant `message_end`, final assistant text captured,
   `report_result` args captured FIRST-WINS, turn/tool/compaction
   counters, signature ring for loop detection.
6. `agent_settled` -> best-effort `get_session_stats` (authoritative
   usage + context %) -> close stdin -> finalise. Forgiving handoff:
   no structured report => final assistant text IS the report.

## Termination ladder

abort -> bounded wait -> close stdin -> bounded wait -> SIGTERM group
-> deadline -> SIGKILL group (`taskkill /T /F`). A `cancelling` flag
makes the ladder own the outcome — settled/exit handlers cannot race
it (this was a real bug: an abort-triggered `agent_settled` used to
finalise the run as `completed` mid-cancel).

## Watchdogs (lazy 1s tick, stopped when idle)

- Wall clock `timeoutSeconds` -> timed_out.
- Max turns: steer wrap-up at `maxTurns`; hard abort after
  `graceTurns`.
- Stall (invariant 17): no progress event for `stallTimeoutSeconds`
  -> steer EXACTLY ONCE; second hit aborts (timed_out + `stall` +
  `partial`). Progress resets the steer budget.
- Loop (invariant 18): signature ring (tool name + hashed key args);
  >= `loopThreshold` -> steer once; threshold+2 after steering ->
  abort (cancelled + `loop` + `partial`).

## Abnormal-exit net (invariant 6)

`shutdown()` force-kills every tree (session_shutdown); a
module-level process `exit` hook (registered once, PID registry)
covers abnormal parent exit. NO database writes — spend is the
in-memory accumulator behind `getStatusSnapshot()`.

## Run states

Run lifecycle states (queued → running → completed/failed/aborted/
timed-out) drive the status snapshot and the footer line; stall and loop
watchdogs steer-then-abort stuck runs; cancellation walks the full
termination ladder (SIGTERM → SIGKILL → tree kill); abnormal parent exit
is covered. NO database writes — spend is the in-memory accumulator
behind `getStatusSnapshot()`.
