## Purpose

The plumbing every feature module may import: persistent path resolution
(`paths.ts`), the user-preferences store (`config.ts`), the shared SQLite
connection (`db.ts`), the stdout-diagnostics gate (`debug-log.ts`) and the
help registry (`help-registry.ts`). Owns no pi events, no UI. Depends on
nothing inside the extension except that `debug-log`/`config` use `paths`.

## Public API & contracts

### paths.ts — package root + data dir

- `getPackageRoot()` — walks up `MAX_PARENT_WALK` (8, then 32 as safety net)
  from `__dirname` looking for `package.json` with name `pi-aftc-toolset` or
  the `extensions/aftc-toolset/index.ts` shape; THROWS when not found.
- `getPersistentRoot()` — per-user dir OUTSIDE the installed package
  (survives `pi update`): Windows `%APPDATA%\pi-aftc-toolset`, macOS
  `~/Library/Application Support/pi-aftc-toolset`, Linux
  `$XDG_DATA_HOME/pi-aftc-toolset` (fallback `~/.local/share/...`).
  Override: `AFTC_TOOLSET_DATA_ROOT` (test harnesses/power users).
- `getDataDir()` = `<persistentRoot>/data`; `getDbFile()` → `turns.db`;
  `getConfigJson()` → `config.json`; `getSshJson()` → `ssh.json`.
- `getRuntimeRoot()` / `getLegacyDataDir()` — LEGACY
  `<packageRoot>/.pi-aftc-toolset[/data]`, migration source only.
- `migrateLegacyData()` — two-phase, lock-safe, idempotent: copy legacy
  files forward (never overwriting), then best-effort delete + tidy. Run by
  index.ts before any module reads the data dir (1.1).

### config.ts — config.json preferences

- **NO in-memory cache (binding rule):** every `getPreference` hits disk;
  `setPreference` is a fresh read-modify-write. pi keeps modules alive
  across `/new`, so a cache would serve stale values and later clobber
  hand edits. Atomic writes (tmp + rename).
- First access creates `config.json` from `DEFAULT_PREFERENCES` (a legacy
  `state.json` is renamed forward).
- Defaults-driven write-back migration: missing/wrong-typed keys are
  backfilled and re-saved automatically; `notifyEnabled` is special-cased
  (derived ON when the user already had sounds configured). Retired keys
  are stripped via `RETIRED_KEYS` (`notifySound`, `aftcCodexInjectMode`,
  `aftcCodexAutoAddEntries` — never prune this list).
- Adding a preference = `Preferences` interface + `DEFAULT_PREFERENCES`;
  retiring = remove both + one `RETIRED_KEYS` line. No other migration code.

### db.ts — shared SQLite

- Lazy singleton `getDb()` over `better-sqlite3`; returns `null` forever if
  the native binding is missing (one console warning pointing at
  `/aftc-install`). `isDbAvailable()` reports the load-time state.
- Schema: `turns` (one row per assistant turn: metrics + prompt-type
  classification flags, never prompt text — 20 columns incl. migrations) +
  `tasks` (one row per settled task: session_id, prompt_index, timestamp,
  task_ms, stop_reason, model_name, thinking_level, turn_count). Indexes on
  timestamp/turn. Column migrations run idempotently after the schema.

### debug-log.ts — /aftc-debug-log-on|off

Toggles `debugLoggingEnabled`; the gate on `aftcConsole.log` stdout echo
(errors never gated; every line still lands in `<dataDir>/debug.log`).
Reports the new state via emphasis (TUI) or print (headless).

### help-registry.ts — /aftc-help source of truth

`registerHelpEntry({command, args?, description, category, aliases?})` —
called next to every `pi.registerCommand`. Categories in
`HELP_CATEGORY_ORDER`: General, Response, Interrupt, Navigation,
"Footer / cache / timing", "Usage report", SSH, Replay, "Keep it short",
aftc-codex, Thinking, "Audio notification", Providers. One entry per PRIMARY
command; aliases inside the entry. The tests/ folder enforces this both ways (see AGENTS.md)
two-way sync with the real registrations.

## Runtime states / failure modes

- Unreadable/corrupt config.json → defaults returned, error logged, pi boots.
- better-sqlite3 missing → `getDb()` null; footer line 4 and usage features
  degrade to zeros/messages; `/aftc-install` fixes it.
- Package root not found → hard throw (better than a silently wrong path).
