## Function

`/usage-report` aggregates the whole turns/tasks/errors history (1.4.4)
into a JSON payload, seeds the report web app into the data dir and starts
its local server, which opens the report in the browser. `/usage-clear`
wipes the DB behind a confirm. Source: `usage-report.ts` (~1500 lines,
class `UsageModule`). Does not import core.ts or usage-recording.ts — it
only reads the shared DB.

Why a web app + server instead of a single HTML file: the old report
embedded ~600 lines of JS in a TS template literal (an escape-mangling
bug class; uneditable), and serving over localhost makes ES modules and
`fetch()` work — both are blocked on `file://` pages.

## /usage-report flow (runReport)

1. `collectReportData()` — read-only DB aggregation. Returns null when
   better-sqlite3 is unavailable → error message, command aborts.
2. `ensureReportFiles()` — seed -> live sync. Copies the shipped app
   (`extensions/aftc-toolset/data/usage-report/`, `reportSeedDir`) into
   `<dataDir>/usage-report/` (`reportLiveDir`) when the live dir is
   missing or its `.usage-report-version` stamp is older than
   `usageReportVersion` in `data/extension-config.json`
   (`shippedReportVersion` vs `liveReportVersion`). These are program
   files, not user data — re-copying on a version bump is safe.
   `copyDir` recursively overwrites everything EXCEPT `data.json`.
3. `writeReportJson(data)` — writes a fresh `<live>/data.json` (the
   only generated file; the seed's `data.json` is a `{}` placeholder
   and is never copied over).
4. `spawnReportServer()` — win32: `cmd.exe /c start "pi usage report"
   /D <live> start.bat`, detached — the report opens in its OWN
   terminal window; closing that window or Ctrl+C stops the server.
   Elsewhere: detached `node server.js` in the live dir. Fire-and-
   forget (`child.unref()`).
5. Console messages: emphasis "Usage report server starting — your
   browser will open." + info naming the live dir and the stop/idle
   behaviour.

`syncUsageReportFiles()` is a test seam exposing step 2 (tests point
`AFTC_TOOLSET_DATA_ROOT` at a scratch dir).

## Seed website (data/usage-report/, 2.1)

`index.html` (page title + header "PI AFTC Toolset - Usage Report",
"All For The Code" strapline, tab bar, all seven tab panels),
`favicon.png`, `includes/css/styles.css` (dark theme: `--bg:#0f1115`,
orange `#fca02f` brand bar + title mark), Chart.js bundled locally at
`includes/js/libs/chart.umd.min.js` (NO CDN — the report needs no
internet), ES-module JS under `includes/js/`: `app.mjs` entry +
`lib/{format,charts}.mjs` shared helpers + one class per tab:
`tabs/{overview,models,thinking,timings,projections,context,errors}.mjs`.
Plus the zero-dependency `server.js`, `start.bat` / `start.sh`
launchers and the empty `data.json` placeholder.

`app.mjs`: fetches `./data.json`, renders the orange `Generated on:
YYMMDD - HH:MM` line from `generatedAt`, boots the 7 tab classes, wires
tab switching and deep links (`history.replaceState` keeps
`location.hash` = active tab; a hash in the URL opens that tab). If
`window.Chart` is missing, `chartsOk` is false and each chart slot
renders a text fallback (`chartFallback`) — tables and cards are
unaffected.

## Local server (server.js)

Zero-dependency `node:http` static file server for the folder it lives
in, bound to 127.0.0.1. Port: 8713, scanning upwards for a free one
(`USAGE_REPORT_PORT` override). On startup it prints a server-info
banner and opens the default browser. Traversal-safe (normalized path
must stay under the served root, else 403); responses are `no-cache`.
Self-terminating: an idle watchdog exits after 30 minutes without a
request (`USAGE_REPORT_IDLE_MINUTES` override); SIGINT/SIGTERM (Ctrl+C
/ window close) shut it down; with opt-in `USAGE_REPORT_STDIN_GUARD=1`
(non-TTY stdin) it also exits on stdin EOF so a parent can tie its
lifetime.

## Screen: report page (browser, 7 tab regions)

Tab bar (deep-linkable via `location.hash`): **Overview · Costs Per Model ·
Thinking levels · Timings · Projections · Context & Allowance ·
Errors**.

1. **Overview** — six headline stat cards in a 2×3 grid (total cost,
   cost per completed task, user prompts, **User / AI Prompts** with
   the average AI-per-user-prompt ratio as the sub-line, **Worst token
   burner** (the model that used the most tokens EVER — prompts, replies
   and cached context — with the all-time token count in the sub-line and
   an info-icon tooltip) and avg cache hit); daily-spend bar chart (last 30
   days, zero-filled, today orange; the HTML tooltip adds that day's
   most costly / cheapest model — cheapest hidden when $0 — and longest
   completed task, white labels + orange values); cost-share doughnut
   with an on-theme window selector (10 windows — Last 24 Hours
   rolling, 1/3/5 Days, 1 Week, 1/3/6 Months, 1 Year, All Time —
   default 3 Days; calendar windows anchor to local midnight / 1st of
   month / Jan 1, precomputed server-side as `shareWindows`, paid turns
   only); and a **2×3 six-pane Period summary**: Last 24 hours (rolling
   window) · Last 3 days · Last Week (Mon to Sun) · This Week (Mon to
   Sun) · This Month · Last Month. Calendar periods anchor to local
   midnight / Monday / 1st of month; lastWeek / lastMonth are bounded
   (upper window bound) so this week/this month never leak in. Each
   pane: total cost, `Prompts: User N / AI M`, then two sections split
   by an hr — **Best AI Models** and **Worst AI Models** — each with 5
   per-metric rows (all ALWAYS shown; an uncomputable metric renders
   N/A with an info-icon tooltip giving the reason). Best: cheapest
   model ($/turn), best value per task ($/completed task), fastest
   tasks, most efficient prompting (fewest AI auto-turns per prompt),
   best cache hit.
   Worst: most costly model, most costly per task, longest task time,
   auto-prompt hog (info-icon tooltip), worst cache hit. COST rows only consider models
   that cost something in the window; cache / timing / ratio rows
   consider ALL models ($0 subscription models are judged on everything
   but cost). Time values use `Xh Ym Zs`.
2. **Costs Per Model** (renamed) — the hero/shame cost ranking: a
   per-model sortable table with a period selector (24h / 7d / 28d /
   All time, default All). Costs are **avg cost per turn** (cost ÷
   turns — the model's price, independent of usage volume). Columns:
   model (+ **Provider** — which provider the model runs through, so
   same-named models from different providers are told apart), Turn Cost, Avg Task $ (with task count), **User / AI**
   (merged prompts column, info tooltip explains it), Avg $/Pup,
   context (% of window — plain text, no fill bar), errors
   (centred), task time, and a **Verdict** column of badges computed
   per period (Best value / Most expensive from $/task paid-only;
   Fastest / Slowest; Most efficient / Auto-prompt hog; Error-prone;
   Context hog / Low context). Every badge shows a "why" tooltip on
   hover (same as the info icons) and is non-selectable; a model only
   earns a verdict when more than one model can be compared, so one
   model never shows both Context hog and Low context. Info-icon
   tooltips on the non-obvious columns; an **avg cost per turn by model** horizontal bar chart
   (top 8) follows the period. No bar fills — the table stays compact
   without horizontal scrolling.
3. **Thinking levels** — per-model × thinking-level sortable table, same
   period selector: cost, **Avg Task $**, a merged **User / AI** column
   (info tooltip), Avg $/Pup, Avg cache, Avg think, Avg response and a
   trailing Task Time column — numeric columns centre-aligned, same
   info tooltips.
4. **Timings** — Task Time analysis from the tasks table: headline
   cards (avg / longest task, turns per task, error & abort counts —
   aborts are a stat here, never shamed); task-time-by-model (top 8)
   and daily avg task-time charts; think / respond split; user- vs AI-turn timings; top-10 longest COMPLETED tasks.
5. **Projections** — usage-rate cost projections (rebuilt v1.21.x).
   Period selector scopes the rate. Cards: avg $/turn, avg $/completed
   task (+ task count), tasks per active day, projected next 30 days,
   projected next 365 days. Per-model table: active days, tasks done,
   turns, $/turn, $/task, tasks/day, $/day, and projected 7/30/90/365
   day spend = tasksPerDay × costPerTask × N. Rows with < 7 active
   days are flagged `~`; ZERO-cost model rows are excluded entirely.
   The note states the active-day-pace basis (idle days not counted)
   and that the calendar-day burn rate lives on the Overview cards.
6. **Context & Allowance** (new v1.21.x) — context-window pressure and
   provider allowance consumption. Cards: 5h token burn, 7d token burn,
   **1M-window rate** (1M-token windows burned per 5h — >1x means a 1M
   context window is unsustainable), current 5h / weekly allowance used
   (latest provider snapshot, N/A when unreported). A 5h burn-by-model
   chart (window equivalents per 5h). A context table (per model ×
   thinking): window, tasks, avg start / avg end context, % of window
   (coloured bar), growth per task, **Tasks to full** (red ≤ 3, amber
   ≤ 10), 5h burn, 5h / window, and the **1M flag** (red pill when a
   model burns ≥ 1,000,000 tokens per 5h — "impossible to use a 1M
   context window at this rate"). The 5h / window and 1M-flag columns
   only apply to models that ACTUALLY report an allowance window
   (subscription plans only — Codex, Claude, MiniMax, Z.ai GLM, Kimi;
   recorded per task as allowance_reported, footer line-5
   availability); API providers (DeepSeek etc.) show N/A — they have no
   5h usage window. An allowance table (per provider):
   avg 5h %/task, avg weekly %/task, used %, 5h resets, tasks until 5h
   full and tasks until weekly full. Context start/end come from pi's
   `getContextUsage()` recorded per task; old rows fall back to
   turn-derived values. Allowance is provider-reported (Codex, Claude,
   MiniMax, Z.ai GLM, Kimi only); other providers show the empty state.
7. **Errors** (new v1.21.x) — failed calls, the unreliable models.
   Cards: failed calls, error rate (failed ÷ completed tasks), failing
   models, most common type. Charts: failed calls by model (bar, top
   8), by type (doughnut: rate limit / overloaded / not found / auth /
   timeout / network / other), per day (last 30 days). Sortable table
   per model × error type with count, % of all, last seen and a fair
   error rate (errors ÷ that model's completed tasks). User aborts are
   NOT errors — they are a stat on Timings. Errors are recorded by
   core.ts on the failing `message_end` into the `errors` table and
   classified by `classifyError()` (order: 429/rate-limit, 5xx/
   overloaded, 404/not-found, 401-403/auth, 408/timeout, network
   keywords, else other).

Money formatting (normative, shared with the footer): $0 → `$0.00`;
< $1 → 4 decimals; $1–<$1,000 → 2 decimals; ≥ $1,000 → whole with
thousands separators. Client `fmtMoney` (`lib/format.mjs`) mirrors
server-side `fmtMoneyServer`. The Models tab adds `$ / turn` and
`$ / task` columns; all money everywhere uses these formatters.

## Runtime states

- No DB / empty DB → report still generated (zeroed) — the command
  does not fail; `/usage-clear` reports "already empty".
- better-sqlite3 missing → both commands print an error pointing at
  `/aftc-install`.
- Headless `/usage-clear`: no overlay, proceeds after the count
  message path (confirm skipped only when no UI).
- Port 8713 busy → server scans upwards. No internet needed: Chart.js
  ships locally; charts, tables and cards all work offline.
- Server never lingers: window close / Ctrl+C stops it; the idle
  watchdog self-exits after 30 minutes without a request.
- Old data (pre-v1.21.x): context columns are 0 and allowance columns
  NULL — the context/allowance tabs fall back to turn-derived context
  and show N/A for allowance; the scoreboard context rows show N/A
  with a reason tooltip.

## Commands

| Command | Args | Behaviour |
| --- | --- | --- |
| `/usage-report` | — | Flow above (seed -> data.json -> server -> browser). Help category "Usage report". |
| `/usage-clear` | — | Counts rows; empty → "already empty" notice. Else AFTC confirm overlay (1.3.2): "Permanently delete all N recorded turns, M task records and K error records from the SQLite database?" → deletes all three tables' rows. |

## Rules / invariants

- Failed tasks (error/abort) are recorded but NEVER averaged into Task
  Time — `stop_reason='complete'` rows only (matches footer line 4,
  1.4.2). Error ROWS (failed LLM calls) are never averaged either; they
  are counted per model × type with a fair rate over completed tasks.
- Cost averages / cost rows / projections use paid-only denominators —
  free / $0 (subscription) models are excluded from everything that
  needs a price, but stay visible for task-time, ratio, cache and
  context judgment.
- Prompt/response text is never read or rendered — metrics only (1.4.4).
- Seed -> live is copy-only and never touches the live `data.json`;
  the app files are program files re-copied on `usageReportVersion`
  bumps (2.1). This doc's tabs are mirrored in the app's own
  `data/usage-report/readme.md`.
- The 1M flag is a burn-rate statement: a model that burns ≥ 1,000,000
  tokens in 5 hours cannot sustain a 1M-token context window at that
  rate — shown as a red "1M window impossible" pill.
