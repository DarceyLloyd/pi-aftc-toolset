## Function

`/usage-report` aggregates the whole turns/tasks history (1.4.4) into a
self-contained HTML file — embedded CSS + JSON + JS, only external ref the
Chart.js 4.4.7 CDN (offline: tables work, charts degrade) — writes it to
`<dataDir>/report.html` (1.2) and opens it in the browser. `/usage-clear`
wipes the DB behind a confirm. Source: `usage-report.ts` (1843 lines, class
`UsageModule`). Does not import core.ts or usage-recording.ts — it only
reads the shared DB.

## Commands

| Command | Args | Behaviour |
| --- | --- | --- |
| `/usage-report` | — | Build + write + open report.html. Help category "Usage report", labelled ALPHA. |
| `/usage-clear` | — | Counts rows; empty → "already empty" notice. Else AFTC confirm overlay (1.3.2): "Permanently delete all N turns and M task records?" → deletes both tables' rows. |

## Screen: report.html (browser page, 5 tab regions)

Tab bar (deep-linkable via `location.hash`): **Overview · Models ·
Thinking levels · Timings · Projections**. Dark theme (`--bg:#0f1115`,
orange `#fca02f` brand bar + title mark). Client JS is plain string
concatenation (lives inside a TS template literal — no backticks/`${}`).

1. **Overview** — headline stat cards (total cost, prompts, calls, cache
   hit, active days); daily-spend bar chart (last 30 days); cost-share
   doughnut; 24h / 7d / 28d period summary cards each with a per-model
   scoreboard (only models that COST something in the window; includes an
   Avg Task Time row from the tasks table).
2. **Models** — per-model sortable table with a period selector
   (daily/weekly/monthly/all): cost, turns, user prompts, AI prompts,
   AI-per-user-prompt, avg cost per user prompt, avg cache rate, avg
   thinking/response ms, Task Time column; cost-by-model bar chart.
3. **Thinking levels** — per-model × thinking-level sortable table, period
   selector, Task Time column.
4. **Timings** — Task Time analysis from the tasks table: headline cards
   (avg / longest task, turns per task, error & abort counts); task-time-
   by-model and daily avg task-time charts; think / respond /
   tools-and-overhead split; user- vs AI-turn timings; top-10 longest
   COMPLETED tasks.
5. **Projections** — overall burn rate (avg $/day from calendar days since
   first turn, projected month/year; estimate flag < 14 days) + per-model
   × thinking $/day, $/week, $/month, $/year from `spend ÷ ACTIVE days`
   (week ×7, month ×30.44, year ×365; rows < 7 active days flagged as
   estimates). Zero-cost model rows excluded.

Money formatting (normative, shared with the footer): $0 → `$0.00`; < $1 →
4 decimals; < $1000 → 2 decimals; ≥ $1000 → whole with thousands separators.

## Runtime states

- No DB / empty DB → report still generated (zeroed) — the command does
  not fail; `/usage-clear` reports "already empty".
- Headless `/usage-clear`: no overlay, proceeds after the count message
  path (confirm skipped only when no UI).
- Offline: charts absent, tables intact.

## Rules / invariants

- Failed tasks (error/abort) are recorded but NEVER averaged into Task
  Time — `stop_reason='complete'` rows only (matches footer line 4, 1.4.2).
- Prompt/response text is never read or rendered — metrics only (1.4.4).
