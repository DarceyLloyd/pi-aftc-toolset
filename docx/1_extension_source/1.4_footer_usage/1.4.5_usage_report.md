## Function

`/usage-report` aggregates the whole turns/tasks history (1.4.4) into a
JSON payload, seeds the report web app into the data dir and starts its
local server, which opens the report in the browser. `/usage-clear`
wipes the DB behind a confirm. Source: `usage-report.ts` (1045 lines,
class `UsageModule`). Does not import core.ts or usage-recording.ts —
it only reads the shared DB.

Why a web app + server instead of a single HTML file: the old report
embedded ~600 lines of JS in a TS template literal (an escape-mangling
bug class; uneditable), and serving over localhost makes ES modules and
`fetch()` work — both are blocked on `file://` pages.

## /usage-report flow (runReport)

1. `collectReportData()` — read-only DB aggregation (unchanged from the
   old architecture). Returns null when better-sqlite3 is unavailable →
   error message, command aborts.
2. `ensureReportFiles()` — seed -> live sync. Copies the shipped app
   (`extensions/aftc-toolset/data/usage-report/`, `reportSeedDir`) into
   `<dataDir>/usage-report/` (`reportLiveDir`) when the live dir is
   missing or its `.usage-report-version` stamp is older than
   `usageReportVersion` in `data/extension-config.json`
   (`shippedReportVersion` vs `liveReportVersion`). These are program
   files, not user data — re-copying on a version bump is safe.
   `copyDir` recursively overwrites everything EXCEPT `data.json`.
3. `writeReportJson(data)` — writes a fresh `<live>/data.json` (the
   only generated file; the seed's `data.json` is a `{}` placeholder
   and is never copied over).
4. `spawnReportServer()` — win32: `cmd.exe /c start "pi usage report"
   /D <live> start.bat`, detached — the report opens in its OWN
   terminal window; closing that window or Ctrl+C stops the server.
   Elsewhere: detached `node server.js` in the live dir. Fire-and-
   forget (`child.unref()`).
5. Console messages: emphasis "Usage report server starting — your
   browser will open." + info naming the live dir and the stop/idle
   behaviour.

`syncUsageReportFiles()` is a test seam exposing step 2 (tests point
`AFTC_TOOLSET_DATA_ROOT` at a scratch dir).

## Seed website (data/usage-report/, 2.1)

`index.html` (page title + header "PI AFTC Toolset - Usage Report",
"All For The Code" strapline, tab bar, all five tab panels),
`favicon.png`, `includes/css/styles.css` (dark theme: `--bg:#0f1115`,
orange `#fca02f` brand bar + title mark), Chart.js bundled locally at
`includes/js/libs/chart.umd.min.js` (NO CDN — the report needs no
internet), ES-module JS under `includes/js/`: `app.mjs` entry +
`lib/{format,charts}.mjs` shared helpers + one class per tab:
`tabs/overview.mjs`, `tabs/models.mjs`, `tabs/thinking.mjs`,
`tabs/timings.mjs`, `tabs/projections.mjs`. Plus the
zero-dependency `server.js`, `start.bat` / `start.sh` launchers and the
empty `data.json` placeholder.

`app.mjs`: fetches `./data.json`, renders the orange `Generated on:
YYMMDD - HH:MM` line from `generatedAt`, boots the 5 tab classes, wires
tab switching and deep links (`history.replaceState` keeps
`location.hash` = active tab; a hash in the URL opens that tab). If
`window.Chart` is missing, `chartsOk` is false and each chart slot
renders a text fallback (`chartFallback`) — tables and cards are
unaffected.

## Local server (server.js)

Zero-dependency `node:http` static file server for the folder it lives
in, bound to 127.0.0.1. Port: 8713, scanning upwards for a free one
(`USAGE_REPORT_PORT` override). On startup it prints a server-info
banner and opens the default browser. Traversal-safe (normalized path
must stay under the served root, else 403); responses are `no-cache`.
Self-terminating: an idle watchdog exits after 30 minutes without a
request (`USAGE_REPORT_IDLE_MINUTES` override); SIGINT/SIGTERM (Ctrl+C
/ window close) shut it down; with opt-in `USAGE_REPORT_STDIN_GUARD=1`
(non-TTY stdin) it also exits on stdin EOF so a parent can tie its
lifetime.

## Screen: report page (browser, 5 tab regions)

Tab bar (deep-linkable via `location.hash`): **Overview · Models ·
Thinking levels · Timings · Projections**.

1. **Overview** — six headline stat cards (total cost, user prompts,
   AI prompts, avg cost per user prompt, avg cache hit, active days);
   daily-spend bar chart (last 30 days, zero-filled, today orange);
   cost-share doughnut with an on-theme window selector (styled like
   the Period selects) offering 10 windows — Last 24 Hours (rolling),
   1 Day, 3 Days, 5 Days, 1 Week, 1 Month, 3 Months, 6 Months, 1 Year,
   All Time — default selection 3 Days; calendar windows anchor to
   local midnight / 1st of month / Jan 1 (footer timeframe semantics),
   data precomputed server-side as `shareWindows` (10 entries, cost-
   by-model, paid turns only) in `collectShareWindows`; top 7 models +
   Other, total in the centre, share % in the legend; chart updates in
   place (the panel title carries no window text); 24h / 7d / 28d
   period summary cards each with a per-model scoreboard. All 13 rows
   are ALWAYS shown — an uncomputable metric renders N/A with an
   info-icon tooltip giving the reason (nothing silently disappears).
   The COST rows (cheapest / most costly) only consider models that
   cost something in the window (a cost average over $0 subscription
   models is meaningless); the usage / cache / timing rows consider ALL
   models. Rows, in order: cheapest model, most costly model, most used
   model (by user-prompt count), least used model, **Avg Task Time**
   (mean wall-clock prompt→settle over the window's completed tasks,
   from the tasks table; value column carries the task count),
   **Longest Avg Task Time** / **Shortest Avg Task Time** (completed
   tasks only, grouped by model × thinking level; each names the
   model, value column carries the thinking level + formatted average
   time), best/worst cache hit, best/worst response time, best/worst
   think time. The three task-time rows all render N/A when the window
   has no completed tasks. Time values use `Xh Ym Zs` format; no
   colour coding on scoreboard rows.
2. **Models** — per-model sortable table with a period selector
   (Last 24 hours / Last 7 days / Last 28 days / All time, default All
   time): cost, turns, user prompts, AI prompts, AI-per-user-prompt,
   avg cost per user prompt, avg cache rate, avg response time, Task
   Time column; info-icon tooltips on the non-obvious columns;
   cost-by-model horizontal bar chart (top 8) that follows the
   selected period.
3. **Thinking levels** — per-model × thinking-level sortable table
   (one row per combination), same period selector, avg think/response
   times and a trailing Task Time column, same info tooltips.
4. **Timings** — Task Time analysis from the tasks table: headline
   cards (avg / longest task, turns per task, error & abort counts);
   task-time-by-model (top 8) and daily avg task-time charts; think /
   respond / tools-and-overhead split; user- vs AI-turn timings;
   top-10 longest COMPLETED tasks.
5. **Projections** — overall burn rate (avg $/day from calendar days
   since first turn, projected month/year; estimate flag < 14 days) +
   per-model × thinking $/day, $/week, $/month, $/year from `spend ÷
   ACTIVE days` (week ×7, month ×30.44, year ×365; rows < 7 active
   days flagged as estimates). Zero-cost model rows excluded.

Money formatting (normative, shared with the footer): $0 → `$0.00`;
< $1 → 4 decimals; $1–<$1,000 → 2 decimals; ≥ $1,000 → whole with
thousands separators. Client `fmtMoney` (`lib/format.mjs`) mirrors
server-side `fmtMoneyServer`.

## Runtime states

- No DB / empty DB → report still generated (zeroed) — the command
  does not fail; `/usage-clear` reports "already empty".
- better-sqlite3 missing → both commands print an error pointing at
  `/aftc-install`.
- Headless `/usage-clear`: no overlay, proceeds after the count
  message path (confirm skipped only when no UI).
- Port 8713 busy → server scans upwards. No internet needed: Chart.js
  ships locally; charts, tables and cards all work offline.
- Server never lingers: window close / Ctrl+C stops it; the idle
  watchdog self-exits after 30 minutes without a request.

## Commands

| Command | Args | Behaviour |
| --- | --- | --- |
| `/usage-report` | — | Flow above (seed -> data.json -> server -> browser). Help category "Usage report". |
| `/usage-clear` | — | Counts rows; empty → "already empty" notice. Else AFTC confirm overlay (1.3.2): "Permanently delete all N recorded turns and M task records from the SQLite database?" → deletes both tables' rows. |

## Rules / invariants

- Failed tasks (error/abort) are recorded but NEVER averaged into Task
  Time — `stop_reason='complete'` rows only (matches footer line 4,
  1.4.2).
- Prompt/response text is never read or rendered — metrics only (1.4.4).
- Seed -> live is copy-only and never touches the live `data.json`;
  the app files are program files re-copied on `usageReportVersion`
  bumps (2.1).
