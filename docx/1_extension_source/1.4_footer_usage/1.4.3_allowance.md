## Function

Fetches the 5-hour rolling + weekly allowance windows of subscription
providers that expose usable usage endpoints and exposes a cached snapshot
(`AllowanceProvider` → re-exposed on `FooterDataProvider`, rendered as
footer line 5 by 1.4.2). Source: `allowance.ts` (725 lines). Never imports
core.ts or footer-widget.ts.

## Supported providers (verified live)

| Provider id | Mechanism | Endpoint / source |
| --- | --- | --- |
| `openai-codex` (ChatGPT Plus/Pro OAuth) | FETCH | `GET https://chatgpt.com/backend-api/wham/usage` — Bearer OAuth token + `ChatGPT-Account-Id`; `rate_limit.primary_window` (5h) + `secondary_window` (weekly), `used_percent` + `reset_after_seconds` |
| `minimax` / `minimax-cn` (Token Plan) | FETCH | `GET https://www.minimax.io/v1/token_plan/remains` (CN: minimaxi.com) — Bearer subscription key; `model_remains[]` entry `model_name=="general"`; reports REMAINING % (converted) + ms reset times |
| `zai` / `zai-coding-cn` (GLM Coding Plan) | FETCH | `GET https://api.z.ai/api/monitor/usage/quota/limit` (CN: open.bigmodel.cn) — Bearer ZAI key; `data.limits[]` TOKENS_LIMIT unit 3 (5h) + unit 6 (weekly), `percentage` USED + `nextResetTime` epoch ms; `data.level` lite/pro/max |
| `kimi-coding` | FETCH | `GET https://api.kimi.com/coding/v1/usages` — Bearer subscription key; `usage{}` weekly + `limits[]` 5-hour window (duration 300 TIME_UNIT_MINUTE); string numerics, ISO-8601 `resetTime` |
| `anthropic` (OAuth subscription only) | HEADERS | no fetch: `anthropic-ratelimit-unified-5h-utilization/-5h-reset/-7d-utilization/-7d-reset` from every response via `after_provider_response` (0..1 ×100). Absent on plain API keys → line 5 hidden |

All other providers: NOT supported — line 5 stays hidden.

## Refresh strategy

- `session_start` — capture provider, initial fetch (line 5 appears before
  the first prompt).
- `model_select` — re-fetch when the provider changed.
- `agent_end` — refresh after each completed prompt, throttled.
- Periodic 3-minute interval ONLY while a prompt is active (started by
  `before_agent_start`/`agent_start`, stopped at `agent_settled` after one
  final forced query; unref'd, with an idle desync guard that shuts the
  timer down).

Credentials come from pi's public ModelRegistry API (token resolution +
OAuth refresh with file locking); `readStoredCredential()` only for
metadata such as the Codex account id. The extension never reads or writes
auth.json itself.

## Runtime states

- Failure (network/auth/parse/non-200) → snapshot CLEARED; line 5 hides
  until the next successful fetch. Stale numbers are never rendered.
- Successful response missing one window (Kimi drops the 5h entry
  intermittently) → `mergeWindows` over the previous snapshot; the last
  good window stays until its reset time passes (no flicker).
- `formatAdaptiveDuration` renders countdowns: drops zero units, stops at
  minutes once hours/days appear ("05m 30s", "02h 15m", "04d 18h 30m").

## Rules / invariants

- Never hammer endpoints: the throttle + active-prompt-only timer are
  binding.
- Line 5 text assembly lives in `buildAllowanceLine` (footer-widget.ts,
  exported for unit tests): ChatGPT/Codex/OpenAI → single rolling window;
  everyone else → `5h`/`Weekly` segments joined by a divider.
